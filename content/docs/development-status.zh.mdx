Turboism 是面向 Live2D Cubism Editor 的 Java 17 Runtime 增强工具和插件框架。开发围绕可用的框架与产品能力组织，而非已废弃的 M1–M16 迁移序列。

本页面是当前 Stable 发行版 **0.67.4**（标签 `v0.67.4`，发布于 2026-10-24）由源代码支持的快照，并非发布公告；已发布的版本请使用[发布信息源](./use/update-policy)。

## 当前架构

```text
Plugin -> SDK -> Runtime policy -> versioned Adapter/Provider -> Cubism/Editor
```

插件仅依赖 Turboism SDK。Runtime 负责主机访问、生命周期、安全、线程、事务、诊断、兼容性和版本路由。

## 受支持的宿主版本

- Windows x64 是受支持的 Cubism 宿主平台。
- 当前 Stable 发行版 **0.67.4** 与所有 0.67.x Stable 一样，支持 **5.0.00 至 5.3.04** 的全部 20 个已审核 Cubism Editor 版本，并配有按版本路由的 adapter 和 Provider（请参阅[兼容性](/docs/use/compatibility)）。上一个 Stable 0.44.0 仅接纳 5.2.03、5.3.02 和 5.3.03。
- 版本支持不等于功能完全一致：143 项能力中有 129 项在每个版本上都被接纳，覆盖率在 5.3.x 上为 100%，5.2.x 上为 97.9%，5.1.x 上最高 95.1%，5.0.x 上为 90.2%。每一项排除都是有证据支持的版本边界。
- 未列出的 Editor 版本不被声称为兼容，不支持或未经验证的能力会安全地失败关闭。
- macOS 打包仅处于 preview，没有经验证的宿主支持；Linux 只涵盖运行时行为，不是受支持的 Cubism 宿主。

## 发布与交付

- 一个产品身份，三个渠道：`stable`、`beta` 和 `nightly`。
- 0.67 系列的 Stable 发行版为 0.67.0（2026-10-19）、0.67.1（2026-10-20）、0.67.2（2026-10-23）和 0.67.4（2026-10-24）；不存在 0.67.3 发行版。上一个 Stable 是 0.44.0（2026-09-11）。
- 每个发行版发布两个产品下载 `TurboismInstaller-<version>.exe` 和 `turboism-<version>.zip`，以及开发者资产 `turboism-sdk-<version>.jar` 和 `turboism-event-processor-<version>.jar`，每个文件都附带 `.sha256` 文件。
- 产品发布分为只读候选构建和显式受保护的 GitHub 提升步骤。失败的候选会复用既定版本；只有提升步骤才会创建附注标签，并在不重新构建的情况下发布已验证的字节。
- 每次构建都会嵌入全局构建身份：版本、渠道、构建号、源修订和 dirty 标记（`FrameworkBuildInfo`）。
- `api.turboism.dev` 上的发布 API 镜像每个渠道，提供每个资产的 SHA-256 和校验和文件，解析官方镜像与 GitHub 来源，并报告每次发布的下载请求。
- 已审查的发行说明带有简体中文、日文和韩文翻译，并以英文作为回退；摘要不再匹配确切英文段落的翻译会被拒绝，而不是被复用。
- 安装程序提供英文、简体中文、日文和韩文。安装器语言的作用范围仅限于安装器；运行时语言来自运行时 `locale` 设置，插件界面语言跟随 Cubism 环境设置的语言。

## 框架基础

- Java Agent bootstrap、Runtime、SDK、第一方插件、测试框架和集成测试模块。
- 插件 SDK API 范围从 `0.67.0` 开始，在 `1.0.0` 之前结束。下界是最低框架基础版本（忽略 beta、nightly 和 SNAPSHOT 后缀），旧版 `[0.1.0,0.2.0)` 插件会被拒绝。
- 插件元数据 schema 版本 **2**、**3**（新增必需的 `category` 和有界的 `tags`）以及 **4**（新增声明式事件导入与导出），并按版本严格校验。
- 本地插件 JAR 发现、manifest 和 API 范围验证、依赖解析、每个插件一个 ClassLoader、生命周期执行、逆序关闭以及 scope/ClassLoader 清理。
- 每个 JAR 支持有序的多个入口点，并支持整个 JAR 的启动回滚。
- `PluginContext` 服务涵盖日志、路径、本地化、任务、配置、存储、用户文件、事件、操作、UI 贡献项、Cubism 访问和诊断。
- 托管本地 JAR 安装、替换、启用、禁用和卸载。变更会写入 journal 暂存，并在 Cubism 重启后应用；内置框架 shell（`dev.turboism.shell`，在 0.67.0 中取代了独立的 core 插件）是 Runtime 自有的框架代码，不是插件，无法被禁用或卸载。
- 启动 preflight 会在应用前重新验证暂存载荷的身份（SHA-256、大小、描述符哈希），私有 backup/restore 保护失败的替换应用。
- 框架消息 catalog 与第一方插件遵循相同的 locale 矩阵，因此缺失的 catalog 会使构建门禁失败，而不是静默降级为英文。

## 安装器与交付

自 0.67.0 起，每个发行版只提供两个产品下载：

- Windows 原生的 NSIS 安装器 `TurboismInstaller-<version>.exe`，提供可选的托管 GraalVM 组件与安全升级；
- 便携式 `turboism-<version>.zip` 归档。

两者都包含全部内置第一方插件和完整的离线 GraalJS 引擎；GraalVM 运行时仍需单独安装。Full/Thin 四下载布局（`-full` 与 `-thin` 安装器及 ZIP）仅存在于 0.67.0 Beta 版本中，现已退役。0.44.0 及更早的版本采用旧版构件（`TurboismInstaller-<version>.exe`、Java 17 IzPack 安装器 `TurboismInstaller-<version>.jar` 以及 `turboism-<version>-full.zip` / `turboism-<version>-lite.zip`）。Java 安装器已不再发布。

安装器没有模式选择页或插件勾选页。自 0.67.4 起，Windows 安装器使用 Turboism 品牌，并隐藏提权后的配置控制台。在 Cubism Editor 中，顶部菜单更名为 **Turboism**（原为“插件”/Plugins 菜单），提供应用内**插件市场…**、**管理插件…**、**插件设置…**（专用双栏窗口）、**检查更新**，以及经签名验证的第一方插件后台自动更新。

安装器在通过四项必需确认和完整的本地化运行时声明之后才进行安装。`config.json` 有明确的更新归属：在现有有效配置上安装时保留用户设置。Windows 配置器只列出确切受支持的 Cubism 安装，并将 Turboism 自有的快捷方式与官方 BAT 集成分开。自 0.67.0 起，安装器默认勾选官方 Cubism BAT 集成：它会备份并修改所选的 `CubismEditor5.bat` 启动器，使现有的 Cubism 快捷方式和文件关联加载 Turboism。该选项可在启动选项页取消勾选，带哈希保护且幂等，卸载时会还原，静默安装时同样生效，并且是唯一通过 UAC 提权的步骤。

## Cubism 和 Editor API 进展

- 统一的对象图覆盖 Canvas、Parameters、Parameter Groups、Parts、Drawables、Deformers、Warp 和 Rotation Deformers、Glue、parameter bindings 以及 texture atlases。
- Core 支持的读取使用不可变复制数据、版本规范化、绑定 generation 的过期引用拒绝和固定 digest 的 resolver 证据。
- parameter 创作路径将 `Parameter.setValue` 连接到 Editor 操作、权限检查、Undo、脏状态处理、刷新和过期目标拒绝。
- Part 显示名称写入在 5.2.03 和 5.3.02 上具有真实主机证据。Part opacity 创作写入要求 5.3.00–5.3.04（已在 5.3.02 上完成实机验证），在 5.0.00–5.2.03 上不可用，因为部件形态不透明度访问器是在 Cubism 5.3.00 引入的。
- 确切版本的静态验证记录、选择器契约和 profile 现已覆盖 5.0.00 至 5.3.04 的全部 20 个已审核构建；逐插件和逐能力的版本边界生成在[兼容性](/docs/use/compatibility)页面。
- Parameter 生命周期 hooks 支持有序的同步 `before` 重写、仅变更时的 `on`、正常完成后的 `after`、递归拒绝、有界的观察工作和卸载清理。
- History 现在会投影不可变的语义细节：`HistoryEntry`、`HistoryChange`、`HistoryEditContext`、`HistoryGroup`、`HistoryOrigin`、`HistoryTarget`，并对目标、坐标和分组进行有界验证。这些值不授予任何主机写入权限。
- 动画工作区 SDK（文档、时间轴、轨道、关键帧、场景和播放）在 Cubism 5.2.00–5.3.04 上可用。
- texture-atlas SDK 支持每页尺寸、打包失败诊断和 planner 协商（0.67.2），以及源轮廓和多边形输出页（0.67.4），并对保留的构造函数设有链接门禁。

## SDK 兼容性基线

- 已审查的二进制 API 基线 **v23** 是 0.67.4 的现行发布门禁；v2–v22 作为历史审计保留（v21 是 0.67.0 的基线，v22 是 0.67.2 的基线）。
- v22 新增了 `TextureAtlasPageSize`、按页的 `TextureAtlasLayoutPlan` 构造函数、`TextureAtlasLayoutPlanner.supportsCompleteAtlas()`、带 `Reason` 的 `TextureAtlasPackingException`、`PsdEditFile.openInApplication(String)` 以及 `SettingsControl.FilePath` 变体。对 `SettingsControl` 的穷举 switch 在重新编译时必须添加一个 case。
- v23 新增了 `TextureAtlasLayoutItem` 的可选源 `outline`、`TextureAtlasLayoutPlan.polygonPages`、`TextureAtlasOutline` 的值相等性以及 `TurboismProgressDialog`。现有构造函数签名仍然保留，但新增组件的 record 会改变反射、相等性、`hashCode` 和 `toString`，且保留的原规范构造函数不再提供参数名元数据。没有移除任何现有公开类型或可调用的 JVM 描述符。
- `@Incubating` 标记实验性 API（例如 `TextureAtlasPolygonLayoutPlanner`），这些 API 可能会改变或消失，并被排除在确切基线之外。SDK 仍处于 pre-stable 策略之下，因此未加注解的 API 本身并不代表 SDK 已冻结。

## 更新检查

- Turboism 会针对已部署的发布 API 检查稳定版更新。比较使用安装包内嵌的权威构建号。
- 可用更新以绘图区上的原生 Cubism 提示呈现。点击提示会打开固定的官方下载页；不会自动下载或执行安装程序。
- 更新检查不阻塞界面，最多每 24 小时运行一次，并始终提供手动检查。自动检查在「启动」设置页有独立的持久开关。
- 插件可以通过 canvas-hint UI 能力（`turboism.ui.canvas.hint` 权限）在绘图区显示原生 Cubism 提示，按版本路由到已验证的宿主路径（可用版本请参阅[兼容性](/docs/use/compatibility)）。

## 第一方插件

已审查的 0.67.4 捆绑包包含二十九个插件：文件夹 texture-atlas 布局及 MaxRects-BSSF、Bitmask 嵌套与 Dalsoo 多边形打包算法、texture-atlas 统计、3D 模型导入、帧动画导入、PSD 剪贴蒙版导入、外部 PSD 编辑、mesh 镜像轴编辑、BoundingBox 弯曲变形器镜像、弯曲变形器 Alt 对称、选区画笔、parameter 批量传输、parameter 锁定、physics 编辑、历史面板、最近预览缩略图、命令面板、调色板标签页过滤器、调色板标签样式、场景调色板增强器、UI 主题、剪贴蒙版查看器、性能统计、protected export、WebDAV 自动备份同步、loopback MCP server 和 ACP 代理桥接。内置的 Turboism 菜单、设置、插件管理和更新提示由 Runtime 自有的框架 shell 提供，而不是插件。请参阅[第一方插件](./use/first-party-plugins)。

## 共享插件服务和 UI

SDK 包含以下契约：

- 操作和菜单；
- 主工具栏和调色板工具栏；
- 类型化上下文菜单；
- 与工具包无关的嵌入式面板；
- 覆盖层、状态通知、canvas 提示、对话框和文件选择；
- 类型化插件配置和迁移；
- 插件自有的数据、状态和缓存存储；
- 有界任务和取消；
- 异步主机读取；
- 本地化和诊断；
- 外观、场景表以及选定的 Editor 功能系列。

当匹配的 Provider 或已验证的主机能力不可用时，主机和 UI 系列会安全地失败关闭。伪造或静态测试不会自动证明已为真实主机做好准备。

## 验证模型

验证按成本与风险分层，而不是作为单一未加区分的门禁运行：

```text
focused verification      smallest affected compile or test selection
devCheck                  production compilation plus structural boundaries
checkIntegration          packaged runtime, plugin, bundle, and cross-module behavior
checkCompletedCommit      full automated repository gate for a coherent change
checkRelease              completed-commit plus supply-chain, historical, and installer-artifact checks
host validation           explicit exact-version Cubism execution for the affected feature
```

宿主验证通过受监督的本地队列运行：构建和准备工作可以并行运行，但单个宿主准入锁会串行化真实的 Cubism 会话；完成需要匹配的结构化生命周期和清理证据；归属未知时会将宿主隔离以便检查，而不是终止无关会话。

## 官方目录与插件市场状态

Cubism 内置的“插件市场”客户端与 UI 已就绪，可直接浏览并安装来自 `turboism.dev/plugins` 签名目录的第一方与精选插件。第一方插件支持经过数字签名验证的后台自动更新与热更新（hot-reload），后台更新可在设置中关闭。自 0.67.2 起，插件管理会标注每个插件的 SDK API 范围，并分别显示其为可用、完整和部分功能声明的确切 Cubism 版本；自 0.67.4 起还会显示已安装插件和市场插件的数量。

## 进行中或受版本限制

- 许多统一对象写入方法仍取决于特定版本的 Provider。接口中存在方法并不意味着每个受支持的 Cubism 版本都能执行它。
- 完整的 Editor 创作矩阵在多个操作系列中仍不完整，每个系列的就绪情况记录在 [SDK API 指南](./reference/sdk-api) 中。
- Drawable、Deformer、Glue、mesh、PSD 以及额外的 texture-atlas 工作流需要由消费者驱动的实现和精确验证。
- 主机 UI 附加、高频 hooks 和真实主机就绪度仍是具有精确版本门槛的高风险边界。
- 可以生成 SDK HTML Javadoc 并托管在本站点上，但许多公开声明仍需要更好的说明性注释。

## 当前未作承诺

Turboism 当前不承诺：

- 安装包的签名或公证公开发布渠道；
- 经过验证的 macOS Cubism 宿主支持；
- 框架安装包的自动下载与静默执行（更新检查与后台插件更新已可用；自动框架安装器更新尚不可用）；
- 插件目录条目的发布者签名或撤销；
- 完整的用户面向安装、修复、回滚、恢复和清除 UI；
- 对 Cubism launcher 的全局修改；
- 在每个 Cubism 版本上具有一致的功能就绪度；
- 仅基于伪造、静态或单版本证据的生产就绪度。

## 近期顺序

5. 完成项目、选择和模型树 API。
6. 通过仅依赖 SDK 的插件恢复尚余的第一方工作流。
7. 仅当显式 API、刷新、轮询或回调不足时才添加 hooks。
8. 强化第三方 SDK、打包和发布证据。
