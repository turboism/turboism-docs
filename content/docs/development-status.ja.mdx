Turboism は、Live2D Cubism Editor 向けの Java 17 ランタイム拡張ツールおよびプラグインフレームワークです。開発は、廃止された M1–M16 移行シーケンスではなく、利用可能なフレームワークと製品機能を中心に進められています。

このページは現在の Stable リリース **0.67.4**（タグ `v0.67.4`、2026-10-24 公開）をソースに基づいて切り取ったスナップショットです。リリース告知ではありません。公開されているバージョンは[リリースフィード](./use/update-policy)を参照してください。

## 現在のアーキテクチャ

```text
Plugin -> SDK -> Runtime policy -> versioned Adapter/Provider -> Cubism/Editor
```

プラグインが依存するのは Turboism SDK だけです。ホストへのアクセス、ライフサイクル、安全性、スレッド、トランザクション、診断、互換性、バージョンルーティングは Runtime が担います。

## 対応するホストバージョン

- Windows x64 が対応する Cubism ホストプラットフォームです。
- 現在の Stable リリース **0.67.4** は、すべての 0.67.x Stable と同様に、**5.0.00 から 5.3.04** までのレビュー済み全 20 の Cubism Editor バージョンを、バージョンごとにルーティングされる adapter と Provider を備えた正確なバージョンとしてサポートしています（[互換性](/docs/use/compatibility)を参照）。以前の Stable である 0.44.0 が認定していたのは 5.2.03、5.3.02、5.3.03 のみでした。
- バージョン対応は機能の同等性を意味しません。143 の capability のうち 129 がすべてのバージョンで認定されており、カバー率は 5.3.x で 100%、5.2.x で 97.9%、5.1.x で最大 95.1%、5.0.x で 90.2% です。すべての除外は証拠に基づくバージョン境界です。
- 一覧にない Editor バージョンは互換性があるとは主張されず、未サポートまたは未検証の capability は fail closed で失敗します。
- macOS のパッケージングはプレビューのみで検証済みのホスト対応はありません。Linux はランタイムの挙動のみを対象とし、対応する Cubism ホストではありません。

## リリースと配布

- 1 つの製品アイデンティティに 3 つのチャンネル（`stable`、`beta`、`nightly`）があります。
- 0.67 系の Stable リリースは 0.67.0（2026-10-19）、0.67.1（2026-10-20）、0.67.2（2026-10-23）、0.67.4（2026-10-24）です。0.67.3 リリースは存在しません。以前の Stable は 0.44.0（2026-09-11）でした。
- 各リリースは 2 つの製品ダウンロード `TurboismInstaller-<version>.exe` と `turboism-<version>.zip`、および開発者向け資産 `turboism-sdk-<version>.jar` と `turboism-event-processor-<version>.jar` を公開し、それぞれに `.sha256` ファイルが付属します。
- 製品リリースは、読み取り専用の candidate build と、明示的に保護された GitHub の promotion ステップに分かれます。失敗した candidate は意図した version を再利用し、promotion だけが annotated tag を作成し、再ビルドせずに検証済みのバイトを公開します。
- すべての build は、version、channel、build number、source revision、dirty flag というグローバルな build identity を埋め込みます（`FrameworkBuildInfo`）。
- `api.turboism.dev` の release API は、asset ごとの SHA-256 と checksum file を伴ってすべての channel をミラーし、公式ミラーと GitHub の source を解決し、release ごとの download request を報告します。
- レビュー済みの release notes は、英語をフォールバックとして簡体字中国語、日本語、韓国語の翻訳を伴います。digest が正確な英語セクションと一致しなくなった翻訳は、再利用せずに拒否されます。
- インストーラーは英語、簡体字中国語、日本語、韓国語で提供されます。インストーラーの言語はインストーラーに限定され、ランタイムの言語はランタイムの `locale` 設定から決まり、プラグインのインターフェース言語は Cubism の Environment Settings の言語に従います。

## フレームワーク基盤

- Java Agent bootstrap、Runtime、SDK、first-party plugin、test-framework、integration-test モジュール。
- plugin の SDK API 範囲は `0.67.0` から始まり `1.0.0` の手前で終わります。下限は最低限必要な framework のベースバージョンです（beta、nightly、SNAPSHOT の接尾辞は無視されます）。旧来の `[0.1.0,0.2.0)` plugin は拒否されます。
- plugin メタデータスキーマバージョン **2**、**3**（必須の `category` と上限付きの `tags` を追加）、**4**（宣言された event import と export を追加）。バージョンごとに厳格に検証されます。
- ローカルプラグイン JAR の検出、マニフェストと API 範囲の検証、依存関係の解決、プラグインごとの ClassLoader、ライフサイクル実行、逆順シャットダウン、scope/ClassLoader のクリーンアップ。
- JAR ごとの順序付き複数エントリポイントと、JAR 全体の起動ロールバック。
- ロギング、パス、ローカライズ、タスク、設定、ストレージ、ユーザーファイル、イベント、アクション、UI 貢献、Cubism アクセス、診断のための `PluginContext` サービス。
- ローカル JAR の install、replacement、enable、disable、uninstall のマネージド管理。変更は journal にステージングされ、Cubism の再起動後に適用されます。組み込みの framework shell（`dev.turboism.shell`。0.67.0 で独立した core plugin を置き換えました）は Runtime 所有の framework コードであり plugin ではないため、無効化もアンインストールもできません。
- startup preflight は適用前にステージング済み payload の identity（SHA-256、size、descriptor hash）を再検証し、private backup/restore が失敗した置換適用を保護します。
- フレームワークのメッセージカタログは、first-party plugin と同じ locale matrix に従います。カタログが欠けている場合は、黙って英語に縮退するのではなく build gate で失敗します。

## インストーラーと配布

0.67.0 以降、各リリースの製品ダウンロードは次の 2 つだけです。

- Windows ネイティブの NSIS インストーラー `TurboismInstaller-<version>.exe`。オプションのマネージド GraalVM コンポーネントと安全なアップグレードを提供します。
- ポータブルな `turboism-<version>.zip` アーカイブ。

どちらにもバンドルされたすべてのファーストパーティプラグインと完全なオフライン GraalJS エンジンが含まれます。GraalVM ランタイムのインストールは引き続き別途行います。Full/Thin の 4 ダウンロード構成（`-full` と `-thin` のインストーラーおよび ZIP）は 0.67.0 の Beta リリースにのみ存在し、廃止されました。0.44.0 までのリリースでは従来の資産（`TurboismInstaller-<version>.exe`、Java 17 IzPack インストーラー `TurboismInstaller-<version>.jar`、`turboism-<version>-full.zip` / `turboism-<version>-lite.zip`）が使用されていました。Java インストーラーは公開されなくなりました。

インストーラーにモード選択や個別プラグイン選択の画面はありません。0.67.4 以降、Windows インストーラーは Turboism のブランディングを使用し、昇格された設定コンソールを表示しません。Cubism Editor 内では、トップメニュー名が **Turboism**（以前は「プラグイン」/「插件」）になり、アプリ内の**プラグインマーケット…**、**プラグイン管理…**、**プラグイン設定…**（専用の 2 ペインウィンドウ）、**更新を確認**、および署名検証付きファーストパーティプラグインのバックグラウンド自動更新を提供します。

インストーラーは、4 つの必須の確認事項と完全なローカライズ済みランタイム宣言を前提とします。`config.json` は更新の所有権を明示しており、既存の有効な設定ではユーザー構成が保持されます。Windows の設定ツールは正確に対応する Cubism インストールのみを一覧表示し、Turboism 所有のショートカットを公式 BAT 連携とは分離して管理します。0.67.0 以降、インストーラーは公式 Cubism BAT 連携を既定で選択します。選択された `CubismEditor5.bat` ランチャーをバックアップして変更し、既存の Cubism ショートカットやファイル関連付けから Turboism が読み込まれるようにします。このオプションは起動オプション画面で解除でき、ハッシュで保護され冪等であり、アンインストール時に復元され、サイレントインストールにも適用されます。UAC で昇格するのはこの手順だけです。

## Cubism と Editor API の進捗

- 統合されたオブジェクトグラフが Canvas、Parameters、Parameter Groups、Parts、Drawables、Deformers、Warp および Rotation Deformers、Glue、パラメータバインディング、texture atlas をカバーします。
- Core-backed read は、不変のコピー済みデータ、バージョン正規化、generation に束縛された stale-reference 拒否、digest-pinned resolver evidence を使用します。
- パラメータ編集経路は、`Parameter.setValue` を Editor 操作、権限チェック、Undo、dirty-state 処理、refresh、stale-target 拒否に接続します。
- Part display-name の書き込みには 5.2.03 と 5.3.02 で実ホストの証拠があります。Part opacity の編集書き込みには 5.3.00–5.3.04 が必要（5.3.02 で実ホスト検証済み）であり、パーツフォームの不透明度アクセサが Cubism 5.3.00 で導入されたため 5.0.00–5.2.03 では利用できません。
- 正確なバージョン用の静的検証レコード、selector contract、profile は 5.0.00 から 5.3.04 までのレビュー済み全 20 ビルドを対象としており、プラグインごと・ケイパビリティごとのバージョン境界は[互換性](/docs/use/compatibility)に掲載されています。
- Parameter lifecycle hook は、順序付き同期 `before` 書き換え、変更時のみの `on`、正常完了時の `after`、再帰拒否、上限付き観測処理、アンロード時のクリーンアップをサポートします。
- 履歴は不変の意味的詳細を投影するようになりました。`HistoryEntry`、`HistoryChange`、`HistoryEditContext`、`HistoryGroup`、`HistoryOrigin`、`HistoryTarget`、および target、coordinate、grouping の上限付き検証です。これらの値はホストへの書き込み権限を与えません。
- アニメーションワークスペース SDK（ドキュメント、タイムライン、トラック、キーフレーム、シーン、再生）は Cubism 5.2.00–5.3.04 で利用できます。
- texture-atlas SDK は、ページごとのサイズ、パッキング失敗の診断、planner のネゴシエーション（0.67.2）、およびソースアウトラインとポリゴン出力ページ（0.67.4）に対応し、保持された constructor の linkage gate を持ちます。

## SDK 互換性ベースライン

- レビュー済みのバイナリ API ベースライン **v23** が 0.67.4 の現行リリースゲートです。v2–v22 は履歴監査として保持されています（v21 は 0.67.0、v22 は 0.67.2 のベースライン）。
- v22 では `TextureAtlasPageSize`、ページ単位の `TextureAtlasLayoutPlan` constructor、`TextureAtlasLayoutPlanner.supportsCompleteAtlas()`、`Reason` を持つ `TextureAtlasPackingException`、`PsdEditFile.openInApplication(String)`、`SettingsControl.FilePath` バリアントが追加されました。`SettingsControl` に対する網羅的な switch は、再コンパイル時に case を追加する必要があります。
- v23 では `TextureAtlasLayoutItem` の任意のソース `outline`、`TextureAtlasLayoutPlan.polygonPages`、`TextureAtlasOutline` の値の等価性、`TurboismProgressDialog` が追加されました。既存の constructor シグネチャは残りますが、コンポーネントが増えた record ではリフレクション、等価性、`hashCode`、`toString` が変わり、保持された旧 canonical constructor はパラメーター名のメタデータを公開しなくなりました。既存の public 型や呼び出し可能な JVM descriptor は削除されていません。
- `@Incubating` は `TextureAtlasPolygonLayoutPlanner` などの実験的 API を示し、変更または削除される可能性があり、正確なベースラインから除外されます。SDK は引き続き pre-stable ポリシーの下にあるため、アノテーションのない API であることだけでは SDK が凍結されたことの保証になりません。

## 更新チェッカー

- Turboism はデプロイ済みの release API に対して stable 更新を確認します。比較には、インストール済みパッケージに埋め込まれた正規の build number を使用します。
- 利用可能な更新は、描画領域上のネイティブ Cubism hint として提示されます。クリックすると固定のファーストパーティダウンロードページが開きます。インストーラーが自動でダウンロードまたは実行されることはありません。
- 更新チェッカーは UI をブロックせず、24 時間に最大 1 回実行され、手動チェックは常に利用できます。自動チェックは Startup 設定タブに専用の永続トグルを持ちます。
- plugin は、canvas-hint UI capability（`turboism.ui.canvas.hint` 権限）を通じて、描画領域上にネイティブ Cubism hint を表示できます。検証済みのホストルート（利用できるバージョンは[互換性](/docs/use/compatibility)を参照）を通じてバージョンルーティングされます。

## 共有プラグインサービスと UI

SDK には次の契約が含まれます。

- アクションとメニュー。
- main と palette toolbar。
- 型付き context menu。
- toolkit-neutral embedded panel。
- overlay、status notification、canvas hint、dialog、file selection。
- 型付きプラグイン設定と migration。
- プラグイン所有のデータ、状態、cache storage。
- 上限付きタスクとキャンセル。
- 非同期ホスト読み取り。
- ローカライズと診断。
- appearance、scene-table、選択された Editor feature family。

対応する Provider または検証済みホスト capability が利用できない場合、ホストと UI の各 family は fail closed します。Fake または static test だけでは、実ホスト対応の準備が自動的に確立されることはありません。

## 検証モデル

検証は、1 つの未分化なゲートとしてではなく、コストとリスクに応じて階層化されます。

```text
focused verification      smallest affected compile or test selection
devCheck                  production compilation plus structural boundaries
checkIntegration          packaged runtime, plugin, bundle, and cross-module behavior
checkCompletedCommit      full automated repository gate for a coherent change
checkRelease              completed-commit plus supply-chain, historical, and installer-artifact checks
host validation           explicit exact-version Cubism execution for the affected feature
```

Host validation は監督されたローカルキューを通じて実行されます。build と prepare の作業は並行して実行できますが、単一の host-admission lock が実際の Cubism セッションを直列化し、完了には一致する構造化された lifecycle と cleanup の evidence が必要で、所有権が不明な場合は無関係なセッションを終了させるのではなく、検査のためにホストを隔離します。

## 公式ディレクトリとプラグインマーケットの状況

Cubism 内のプラグインマーケットクライアントと UI は稼働しており、`turboism.dev/plugins` の検証済みディレクトリから署名済みファーストパーティおよびカタログプラグインを直接検索・導入できます。ファーストパーティプラグインは署名検証付きのバックグラウンド自動更新およびホットリロードに対応しており、バックグラウンド更新は設定で無効にできます。0.67.2 以降、プラグイン管理は各プラグインの SDK API 範囲と、利用可能・完全・部分的な機能ごとに宣言された正確な Cubism バージョンを表示します。0.67.4 以降は、インストール済みプラグインとマーケットのプラグインの数も表示します。

## 進行中またはバージョン制限付き

- 多くの unified-object write method は、特定のバージョン Provider に依存しています。インターフェースにメソッドがあることは、サポート対象のすべての Cubism バージョンで実行できることを意味しません。
- 完全な Editor-authoring matrix は、いくつかの operation family でまだ不完全であり、family ごとの準備状況は [SDK API ガイド](./reference/sdk-api)に記録されています。
- Drawable、Deformer、Glue、mesh、PSD、および追加の texture-atlas workflow には、利用者主導の実装と正確な検証が必要です。
- Host UI attachment、高頻度 hook、実ホスト対応は、正確なバージョンゲートを伴う高リスク境界として残っています。
- SDK HTML Javadoc は生成でき、このサイトで公開されていますが、多くの public declaration にはより詳しい説明コメントがまだ必要です。

## 現在約束されていないもの

Turboism は現在、次のものを約束していません。

- インストーラーパッケージの署名またはノータリゼーション済みの公開リリースチャネル。
- 検証済みの macOS Cubism ホスト対応。
- フレームワークインストーラーの自動ダウンロードとバックグラウンド実行（更新チェックとプラグインのバックグラウンド自動更新は利用可能。フレームワークインストーラー自体の自動更新は対象外）。
- プラグインディレクトリ掲載項目の publisher signing または revocation。
- 完全なユーザー向けの install、repair、rollback、recovery、purge UI。
- Cubism launcher のグローバルな変更。
- すべての Cubism バージョンに対する一様な機能準備。
- fake、static、または単一バージョンの証拠だけに基づく本番対応。

## 近い将来の順序

1. unified object と reference model を完成させる。
2. Core reads と version-routed Providers を完成させる。
3. 検証済み consumer から Undo を伴う Editor-owned writes を拡張する。
4. operation lifecycle semantics を標準化する。
5. project、selection、model-tree API を完成させる。
6. 残りの first-party workflow を SDK-only plugin によって復元する。
7. 明示的 API、refresh、polling、callback で不十分な場合に限り hook を追加する。
8. third-party SDK、packaging、release evidence を強化する。

ソースレベルの背景については、[Turboism repository](https://github.com/Turboism/Turboism) と、その `ARCHITECTURE.md` および `ROADMAP.md` ファイルを参照してください。
