## 설치 프로그램이 시작되지 않거나 검증에 실패함

- 패키지가 사용 중인 플랫폼에 맞는지, 공개된 릴리스 또는 공식 미러에서 다운로드했는지 확인하세요.
- 일치하는 `.sha256` 파일로 SHA-256 체크섬을 검증하세요. 값이 다르면 다운로드가 불완전하거나 변조된 것이므로 다시 다운로드하세요.
- `.jar` 설치 프로그램에는 Java 17 이상이 필요합니다.
- 설치 프로그램은 파일을 변경하기 전에 네 가지 필수 확인 항목과 전체 런타임 선언이 모두 수락되어야 합니다.
- 설치 프로그램에는 서명이 없으므로 Windows 또는 macOS에서 알 수 없는 게시자 경고가 표시될 수 있습니다. 운영 체제 보호를 해제하지 말고 대신 체크섬을 확인하세요.

## Turboism이 시작되지 않음

- 의도한 Turboism home과 올바른 Cubism 설치를 위한 관리형 런처를 사용하고 있는지 확인하세요.
- Turboism home의 `logs/` 디렉터리에 있는 런타임 로그를 확인하고, 설정 도구가 남긴 `logs/installer/` 출력도 확인하세요.
- 활성 Cubism 설치가 지원 범위(Windows x64의 Editor 5.2.03, 5.3.02 또는 5.3.03)에 맞는지 확인하세요.
- 신원 확인 실패를 우회하기 위해 Cubism JAR, DLL, BAT 파일 또는 라이선스 구성 요소를 교체하지 마세요.

## 플러그인이 나타나지 않음

다음을 확인하세요:

- 재시작 후 관리형 JAR 설치가 완료되었거나, 수동 JAR이 `<turboism.home>/plugins/`의 루트에 직접 있는지(하위 디렉터리가 아님);
- 두 번의 실행 모두에서 같은 Turboism home을 사용하는지;
- 같은 플러그인 ID를 가진 이전 JAR이 남아 있지 않은지(중복 ID는 `DUPLICATE_PLUGIN_ID`로 실패합니다);
- JAR에 `META-INF/turboism/plugin.json`이 정확히 하나 있는지;
- 매니페스트가 지원되는 `schemaVersion`(2, 3 또는 4)을 선언하고 그 버전에 대해 유효한지;
- 진입점 클래스가 존재하고, public이며, `TurboismPlugin`을 구현하고, public 무인수 생성자를 가지는지;
- Turboism API 범위와 필수 종속성이 해결되는지;
- 플러그인 ID가 비활성화되거나 중복되지 않았는지;
- `environment.requiresCubism`이 현재 환경과 일치하는지.

## JAR이 거부됨

관리형 JAR은 심볼릭 링크나 비정규 소스, 아카이브 크기·항목·확장·압축률 제한 위반, 잘못된 경로, 중복 항목, 특수 파일 또는 `META-INF/turboism/plugin.json`의 누락이나 중복으로 거부될 수 있습니다.

디스크립터 ID·버전·API 범위 불일치, 복사된 SDK·런타임·Live2D 클래스, 네이티브 또는 설치 프로그램 페이로드, 중첩 JAR, 누락된 진입점, 선언되지 않은 리소스 및 선언되지 않은 i18n 카탈로그도 거부됩니다.

현재 플러그인 소스에서 JAR을 다시 빌드하세요. 아카이브를 수동으로 편집하거나 검사를 비활성화하지 마세요. 위 사유는 관리형 사전 검사를 설명합니다. 수동 복사는 이를 건너뛰며, 시작 검증이 강제하는 위반만 런타임 시작 진단에 나타납니다.

## 작업이 계속 대기 중임

플러그인 설치, 교체, 사용, 사용 안 함 및 제거 작업은 Cubism을 재시작한 후에 적용됩니다.

- Cubism이 완전히 종료된 뒤 재시작되었는지 확인하세요.
- 두 번의 실행 모두에서 같은 `turboism.home`을 사용하는지 확인하세요.
- 런타임 상태와 로그를 확인하세요.
- Turboism이 실행 중일 때 플러그인, 구성 및 대기 상태 파일을 편집하지 마세요.

## 호스트 기능을 사용할 수 없음

이는 호스트 버전, Cubism 파일 신원, 매핑 검증, 프로바이더 가용성, 안전 모드 또는 오래된 오브젝트 세대로 인한 의도적인 안전 실패인 경우가 많습니다.

정확한 Cubism 버전, Cubism 파일 신원, 작업 및 진단 코드를 기록하세요. 리플렉션이나 직접적인 호스트 접근으로 실패를 우회하지 마세요.

## 인터페이스 언어가 예상과 다름

- 설치 프로그램 언어는 설치 프로그램에만 영향을 줍니다.
- 런타임 언어는 런타임 `locale` 설정에서 결정됩니다. 명시적인 `-Dturboism.locale` 또는 `config.json`의 로캘이 호스트보다 우선합니다.
- 그 밖의 플러그인 인터페이스 언어는 Cubism Editor의 **File → Environment Settings → General → Language**를 따릅니다.

## Cubism 런처 통합 관련 경고

관리형 런처 통합이 충돌을 보고하면, 공식 BAT 파일 또는 그 백업이 설치 이후 편집된 것입니다. 정리는 해시가 일치하는 관리형 파일만 복원하고 재시도를 위해 상태를 보존합니다. 백업하지 않은 파일을 덮어써서 충돌을 해결하지 마세요.
