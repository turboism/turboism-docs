프레임워크를 개선하거나 확장과 플러그인을 만들어 Turboism을 강화하는 데 도움을 주세요. 다음 원칙을 따르면 기여가 더 많은 사람에게 안정적이고 안전하며 유용하게 됩니다.

## 기여 원칙

- 단일 호스트나 사용 사례를 위한 동작을 추가하기보다 일반적인 프레임워크 경계 안에서 작업하세요.
- 내부 API, 호스트 오브젝트, 리플렉션 또는 지원되지 않는 통합 경로보다 공개 SDK를 우선하세요.
- 각 변경은 하나의 명확한 사용자 또는 개발자 요구에 집중하세요.
- 대상 버전 호환성, 기능 가용성 및 필요한 권한을 각각 별도로 검증하세요. 권한이 부여되었다고 해서 기능을 사용할 수 있다는 것이 증명되지는 않습니다.
- 적절한 테스트를 추가하거나 갱신하고, 영어, 중국어 간체, 일본어 및 한국어 문서를 동기화 상태로 유지하며, 공개 SDK나 그 문서가 변경될 때마다 SDK Javadoc을 다시 생성하고 검토하세요.
- 사용자 파일, 개인 데이터 및 프라이버시를 보호하세요. 필요한 접근과 데이터만 요청하고 처리하며, 코드, 로그 또는 문서에 민감한 정보를 노출하지 마세요.

## 참여 방법

### 1. 프레임워크 개선

[GitHub Issues](https://github.com/turboism/turboism/issues)를 사용해 프레임워크 작업을 보고, 논의하거나 다듬으세요. 구현 변경은 [GitHub Pull Requests](https://github.com/turboism/turboism/pulls)로 제안하세요.

### 2. 확장 개발

작업에 맞는 확장 경로를 사용하세요: 프로세스 내 SDK 통합에는 [Java 플러그인](./designing-plugins)을 만들고, 명시적으로 호출되는 제한된 스크립트에는 [GraalJS 스크립트](./graaljs-scripts)를 사용하며, 신뢰하는 로컬 클라이언트 통합에는 [MCP](./mcp)를 사용하세요.

### 3. 플러그인 디렉터리용 플러그인 개발

플러그인 디렉터리 배포를 염두에 두고 플러그인을 개발하세요. 서명된 디렉터리 클라이언트는 존재하지만 프로덕션 활성화가 준비되지 않았고 서드파티 목록도 실제로 제공되지 않으므로, 공개된 것으로 제시해서는 안 됩니다. 현재로서는 [Turboism GitHub 저장소](https://github.com/turboism)를 통해 후보 플러그인을 제출하거나 논의하세요.
