눈에 보이는 증상에서 출발하세요. 각 섹션은 확인할 가치가 있는 순서대로 가장 가능성이 높은 원인을 나열합니다. 플러그인에 한정되지 않는 설치 프로그램, 시작, 호스트 문제는 [문제 해결 및 피드백](/docs/troubleshooting)을 참고하세요.

## 먼저 증거를 수집하세요

무엇이든 변경하기 전에:

1. **로그를 엽니다.** **Turboism → 로그…** 항목을 선택하고 현재 세션 로그를 확인합니다. 플러그인 ID를 검색하세요. 실패는 플러그인 ID가 붙어 보고됩니다.
2. **플러그인 관리를 확인합니다.** **Turboism → 플러그인 관리…** 항목을 엽니다. 플러그인이 목록에 있다면 두 번 클릭하여 SDK API 범위와 선언된 Cubism 버전을 확인하세요.
3. **버전을 기록합니다.** Turboism 버전, Cubism Editor 버전, 정확한 절차를 기록하세요. 버전에 따른 실패는 흔합니다.

Turboism이 실행 중일 때는 플러그인, 구성, 보류 상태 파일을 편집하지 마세요. JAR를 거부한 검증을 절대로 비활성화하지 마세요.

## 설치할 때 JAR가 거부됨

**JAR에서 설치…** 항목은 먼저 파일을 검사합니다. 다음 사유로 JAR를 거부할 수 있습니다:

- 심볼릭 링크 또는 일반 파일이 아닌 소스, 또는 원시 크기, 항목 크기, 전체 압축 해제 크기, 항목 수, 압축 비율 제한을 초과하는 아카이브;
- 형식이 잘못되었거나 중복된 항목, 특수 파일, 또는 `META-INF/turboism/plugin.json`의 누락이나 중복;
- 디스크립터의 ID, 버전 또는 API 범위 불일치;
- **복사된 SDK, Runtime, 테스트 또는 Live2D 클래스**: 빌드는 SDK를 셰이딩하지 않고 `compileOnly`를 사용해야 합니다;
- 네이티브 바이너리, 설치 프로그램 페이로드 또는 중첩 JAR;
- 진입점 누락 또는 선언되지 않은 일반 리소스;
- `plugin.json`에 선언되었지만 JAR에 없는 i18n 카탈로그.

`./gradlew clean build`로 소스에서 다시 빌드하고 Gradle이 생성한 JAR를 설치하세요. 아카이브를 직접 편집하지 마세요.

## 설치되었지만 나타나지 않음

다음을 확인하세요:

- 작업이 Cubism **완전 재시작 후에 적용**되었고, 두 번의 실행 모두 **같은 Turboism home**을 사용했는지;
- JAR를 수동으로 복사했다면 하위 폴더가 아니라 `<turboism.home>/plugins/`의 루트에 직접 있는지;
- 같은 플러그인 ID의 이전 JAR가 남아 있지 않은지(중복은 `DUPLICATE_PLUGIN_ID`로 실패합니다);
- 플러그인 ID가 **플러그인 관리…** 창에서 비활성화되지 않았는지;
- `environment.requiresCubism`이 시작한 환경과 일치하는지;
- 진입점 클래스가 존재하고, `public`이며, `TurboismPlugin`을 구현하고, public 매개변수 없는 생성자를 가지는지;
- 디스크립터가 지원되는 `schemaVersion`을 사용하고 이에 맞게 유효한지. 알 수 없는 필드는 무시되지 않고 거부되므로 필드 이름의 오타도 로드를 실패시킵니다.

## 호환되지 않음으로 표시됨

플러그인 관리와 플러그인 마켓은 플러그인의 `turboismApi` 범위가 실행 중인 Turboism API를 포함하지 않으면 호환되지 않음으로 표시합니다. 레거시 `[0.1.0,0.2.0)` 범위는 `TURBOISM_API_INCOMPATIBLE`로 실패합니다. `[0.67.0,1.0.0)`을 사용하거나, 더 새로운 SDK 멤버에 의존한다면 더 높은 최솟값을 사용하세요.

## 로드되지만 시작에 실패함

생성, `init` 또는 `enable`에서 예외가 발생하면 Runtime은 JAR 전체를 롤백하며, 예외는 플러그인 ID와 함께 로그에 나타납니다. 일반적인 원인:

- 사용할 수 없는 서비스에 대한 가드 없는 호출([권한과 가용성](/docs/build-a-plugin/key-mechanisms/permissions-and-availability) 참고);
- 누락된 현지화 키 또는 카탈로그;
- 잘못된 구성 스키마(예: 잘못된 키 이름, 중복된 구성 ID 또는 경로);
- 나중에 실행되는 메서드에서만 설정하는 필드로 인한 `NullPointerException`.

해결책은 거의 항상 가드(`isAvailable()`, `services().find(...)`)나 디스크립터 수정이며, 더 넓은 권한이 아닙니다.

## 시작되지만 기능이 아무 동작도 하지 않음

[권한과 가용성](/docs/build-a-plugin/key-mechanisms/permissions-and-availability)의 네 가지 검사를 차례로 따라가 보세요:

1. **권한.** 정확히 그 호출에 대한 권한이 `plugin.json`에 선언되어 있나요? 거부는 플러그인에 대해 로그로 남습니다.
2. **서비스.** `services().find(...)`가 빈 결과를 반환했나요, 아니면 `unavailable()` 센티널이 응답했나요?
3. **Cubism 버전.** 로그에 `CubismEditorApiUnavailableException` 또는 사용할 수 없는 API ID가 보이나요? Editor 버전이 해당 API를 허용하지 않을 수 있습니다. [호환성](/docs/use/compatibility)을 참고하세요.
4. **상태.** 모델 문서가 실제로 활성 상태인가요? 문서가 바뀌어서 보관 중인 오브젝트가 오래된 것은 아닌가요?

또한 `enable()`에서 등록했는지, 핸들을 disposable 스코프에 등록했는지, 플러그인이 설치만 된 것이 아니라 **사용 설정**되어 있는지 확인하세요.

플러그인 내부에서 런타임이 보고한 문제를 드러내고 싶다면 `context.diagnostics()`를 통해 구조화된 진단을 사용할 수 있습니다.

## 메뉴 항목이나 액션이 없음

- 메뉴 경로는 슬래시로 구분된 문자열입니다. 카탈로그에서 가져오는 경우 기본 카탈로그인 `messages.properties`에 키가 존재하는지 확인하세요.
- `turboism.action.register`와 `turboism.ui.menu.contribute`가 모두 필요합니다. 하나는 액션용, 다른 하나는 메뉴 항목용입니다.
- 메뉴 기여는 액션 **ID**를 참조합니다. 어느 쪽이든 오타가 있으면 뒤에 아무것도 없는 메뉴 항목이나 메뉴가 없는 액션이 남습니다.

## 설정이 나타나지 않거나 유지되지 않음

- 스키마를 등록하려면 `turboism.config.plugin.write`가, 읽으려면 `turboism.config.plugin.read`가 필요합니다.
- 스키마는 무엇이든 이를 읽기 전에 `init`에서 등록하고 `config().isAvailable()`로 가드하세요.
- 에디터 필드의 `key`는 스키마에 선언된 키와 일치해야 하며 소문자 `[a-z0-9._-]`를 사용해야 합니다.
- 쓰기는 리비전을 사용합니다. 오래된 리비전은 예외가 아니라 결과 안의 값으로 거부되므로 결과를 확인하세요.

## 여전히 해결되지 않나요?

- 문제를 보여 주는 가장 작은 버전, 가급적 단계 2의 hello 플러그인으로 플러그인을 줄이세요.
- 디스크립터를 [플러그인 매니페스트 및 패키징](/docs/build-a-plugin/manifest) 및 퍼스트 파티 플러그인의 `plugin.json`과 비교하세요.
- 재현 가능한 문제는 버전과 로그 줄을 포함하여 [피드백 및 요청](/docs/report-a-bug)로 알려 주세요. 공유하는 모든 자료에서 개인 경로, 자격 증명, 개인 데이터를 제거하세요.
