Parameter Peek는 아직 인사만 합니다. 이 단계에서는 Editor로부터 두 가지를 알아냅니다. 열려 있는 모델에 파라미터가 몇 개 있는지, 그리고 플러그인이 활성화된 이후 파라미터 값이 몇 번 바뀌었는지입니다.

## 1. 새 권한 추가

모델 데이터를 읽고 변경을 관찰하는 것은 두 개의 위험 경계를 더 넘는 일이며, 이벤트를 받으려면 세 번째 권한이 필요합니다. `plugin.json`의 `permissions`에 다음을 추가합니다:

```json
{ "id": "turboism.cubism.model.read", "scope": "application", "reason": "Counts the parameters of the active model." },
{ "id": "turboism.cubism.model.observe", "scope": "application", "reason": "Counts parameter value changes." },
{ "id": "turboism.event.subscribe", "scope": "application", "reason": "Receives parameter change events." }
```

`model.read`는 모델 오브젝트를 읽을 수 있게 하고, `model.observe`는 모델 변경을 설명하는 이벤트를 받을 수 있게 하며, `event.subscribe`는 이벤트 구독 자체를 가능하게 합니다. 파라미터 이벤트에는 마지막 두 가지가 모두 필요합니다.

## 2. 활성 모델 읽기

`report()`를 교체하고 카운터 필드를 추가합니다. 변경된 부분은 주석으로 표시되어 있습니다.

```java title="ParameterPeekPlugin.java (changed parts)"
import dev.turboism.sdk.cubism.CubismEditorApiUnavailableException;
import dev.turboism.sdk.cubism.event.ParameterValueEvent;
import dev.turboism.sdk.event.SubscribeEvent;
import java.util.concurrent.atomic.AtomicInteger;

public final class ParameterPeekPlugin implements TurboismPlugin {

    private final AtomicInteger observedEdits = new AtomicInteger();   // new
    private PluginContext context;
    private PluginLogger logger;

    // init(), disable(), shutdown() unchanged

    @Override
    public void enable() throws Exception {
        observedEdits.set(0);                                           // new
        // ... action and menu registration unchanged
    }

    @SubscribeEvent                                                     // new
    public void onParameterChanged(final ParameterValueEvent.On event) {
        observedEdits.incrementAndGet();
    }

    private void report() {
        final String summary;
        try {
            if (!context.cubism().hasActiveModel()) {
                summary = context.localization().text("parameterpeek.summary.no-model");
            } else {
                final int count = context.cubism().model().active().parameters().all().size();
                summary = context.localization().format("parameterpeek.summary", count, observedEdits.get());
            }
        } catch (CubismEditorApiUnavailableException unavailable) {
            logger.info("Parameter reading is unavailable on this Cubism version: " + unavailable.apiId());
            return;
        }
        logger.info(summary);
        context.services().find(UiHostCapabilityService.class).ifPresent(ui ->
                ui.notifyStatus(new StatusNotification("parameterpeek.report", "INFO", summary)));
    }
}
```

두 개의 새 메시지를 **두** 카탈로그 파일 모두에 추가합니다:

```properties
parameterpeek.summary=The active model has {0} parameters; {1} value changes observed since enable.
parameterpeek.summary.no-model=Open a model document first.
```

`{0}`과 `{1}`은 `java.text.MessageFormat` 플레이스홀더이며 `localization().format(key, args...)`가 값을 채웁니다. `MessageFormat`이므로 메시지의 리터럴 작은따옴표는 두 번(`''`) 써야 하고, 숫자는 활성 로캘에 맞게 서식이 적용됩니다.

### 핵심 메커니즘: 모델을 보는 두 가지 방법

SDK는 Cubism을 두 가지 시각으로 제공합니다:

- `context.cubism().activeModel()` 같은 **스냅샷**은 변경 불가능한 값 오브젝트입니다. 읽기 비용이 낮고 보관해도 안전하지만, 특정 시점의 상태를 나타냅니다.
- `context.cubism().model().active()`를 통해 접근하는 **오브젝트 모델**은 실시간 `Parameters`, `Parts`, `Drawables` 등을 제공합니다. 이 오브젝트들은 **세대에 바인딩**됩니다. 문서 전환, 리로드, 삭제 또는 프로바이더 교체 후에는 보관 중인 참조가 엉뚱한 대상을 조용히 가리키는 대신 안전하게 실패(fail closed)합니다.

따라서 `Parameter`를 필드에 저장해 두었다가 나중에 재사용하지 마세요. 필요할 때마다 `context.cubism()`에서 다시 해석하세요. 더 넓은 읽기 패턴은 [SDK API 가이드](/docs/reference/sdk-api#스냅샷-및-쿼리-api)를 참고하세요.

### 핵심 메커니즘: 안전하게 실패하고, 그 사실을 알립니다

Cubism 데이터가 항상 존재하는 것은 아닙니다. `report()`가 이를 어떻게 처리하는지 보세요:

1. `hasActiveModel()`은 모델이 아닌 문서라는 흔한 경우를 예외 없이 처리합니다.
2. `CubismEditorApiUnavailableException`은 덜 흔한 경우, 즉 활성 Cubism 버전이 해당 호출을 허용하지 않는 경우를 처리합니다. 기능 경계에서 이를 잡아 사용자에게 도달하게 두지 말고 기능을 축소(여기서는 로그 기록)하세요.

무엇을 할지 결정하려고 Cubism 버전 번호를 문자열로 비교하지 마세요. SDK가 알려 주게 하세요. 같은 원칙이 모든 서비스에 적용됩니다. 권한은 요청할 수 있게 해 줄 뿐 응답을 약속하지는 않습니다. [권한과 가용성](/docs/build-a-plugin/key-mechanisms/permissions-and-availability)을 참고하세요.

## 3. 이벤트에 반응

`ParameterValueEvent`는 세 가지 상태를 가진 sealed 계열입니다:

| 타입 | 발생 시점 | 값을 변경할 수 있나요? |
| --- | --- | --- |
| `Before` | 호스트 쓰기 전에 동기적으로 발생합니다. | 예. 단, 별도의 *intercept* 권한이 필요합니다. |
| `On` | 값을 **실제로 변경한** 쓰기 후에 발생합니다. | 아니요, 관찰만 가능합니다. |
| `After` | 변경되지 않은 쓰기를 포함하여 모든 성공한 쓰기 후에 발생합니다. | 아니요, 관찰만 가능합니다. |

Parameter Peek는 변경 횟수를 세므로 `On`이 알맞은 타입입니다. 관찰에는 `Before`가 필요하지 않습니다.

`@SubscribeEvent`는 선언적 방식입니다. 1단계에서 설정한 `turboism-event-processor` 어노테이션 프로세서가 컴파일 시점에 어노테이션을 읽고 구독자 인덱스(JAR에서 본 `__TurboismSubscriberCatalog` 클래스)를 생성하므로 수동 등록이나 해제가 필요 없습니다. 리스너는 public 클래스의 public 인스턴스 메서드여야 하며, `void`를 반환하고 구체적인 이벤트 매개변수를 정확히 하나 선언해야 합니다. 그 외에는 프로세서가 컴파일 오류로 보고합니다.

대신 직접 구독할 수도 있으며, 이 방식은 프로세서가 없는 SDK에서도 동작합니다. 반환된 핸들은 disposable 스코프에 보관하세요:

```java
Registration subscription = context.eventBus().subscribe(
        ParameterValueEvent.On.class,
        event -> observedEdits.incrementAndGet());
context.disposableScope().register(subscription);
```

하나의 이벤트에는 한 가지 방식만 사용하세요. 둘 다 사용하면 변경이 두 번 집계됩니다.

### 핵심 메커니즘: 이벤트는 사용자의 스레드에서 실행되지 않습니다

일반 이벤트 관찰은 비동기로 전달되고, 수명 주기 메서드는 전환마다 다를 수 있는 워커 스레드에서 실행되며, 메뉴 액션은 또 다른 곳에서 실행됩니다. 플러그인을 동시성 환경으로 취급하세요. 카운터가 `int`가 아니라 `AtomicInteger`인 이유입니다. 리스너는 짧고 블로킹하지 않게 유지하세요. 규칙과 백그라운드 및 UI 작업 스케줄링 방법은 [스레드와 작업](/docs/build-a-plugin/key-mechanisms/threads-and-tasks)에서 다룹니다.

## 4. 지원하는 Cubism 버전 선언

`src/main/resources/META-INF/turboism/cubism-versions.json`을 엽니다. 설정 스크립트가 릴리스에서 검토된 Cubism Editor 버전으로 이 파일을 채웠습니다:

```json title="cubism-versions.json"
{
  "format": "turboism.plugin-cubism-versions/v1",
  "plugin": "com.example.parameterpeek",
  "supportedVersions": ["5.0.00", "5.0.01", "..." , "5.3.04"],
  "fullFeatureVersions": ["5.0.00", "5.0.01", "..." , "5.3.04"]
}
```

- `supportedVersions`는 플러그인을 사용할 수 있는 정확한 Editor 버전을 나열합니다.
- `fullFeatureVersions`는 **모든** 기능이 동작하는 부분집합입니다. `supportedVersions`의 부분집합이어야 합니다.

이 파일은 사용자가 하는 주장이며 SDK가 대신 검사해 주지 않습니다. 두 목록 모두 실제로 테스트한 버전으로 좁히세요. 확신이 없다면 적게 선언하세요. 플러그인 관리는 누락되었거나 잘못된 선언을 **선언되지 않음**으로 표시하며, 사용자는 플러그인 세부 정보에서 두 목록을 볼 수 있습니다.

`@CubismEditor` 같은 SDK 어노테이션은 SDK API가 어떤 버전에서 동작하는지를 설명합니다. 플러그인이 해당 버전에서 동작함을 증명하지는 않습니다. 호환성은 SDK의 선언, 직접 수행한 테스트, 런타임 검사의 조합입니다. 검토된 버전 집합과 Editor 마이너 라인별 capability 경계는 [호환성](/docs/use/compatibility)을 참고하세요.

## 5. 시험해 보기

빌드하고, 다시 설치하고([단계 3](/docs/build-a-plugin/first-plugin/build-and-install#5-편집-빌드-설치-루프) 참고), Cubism을 재시작한 뒤 다음을 수행합니다:

1. 모델이 열려 있지 않은 상태에서 **Parameter Peek: Report**를 실행합니다. `Open a model document first.`가 보여야 합니다.
2. 모델을 열고 다시 실행합니다. 파라미터 수와 `0 value changes`가 보여야 합니다.
3. 파라미터 슬라이더를 몇 번 움직인 뒤 명령을 다시 실행합니다. 변경 횟수가 늘어납니다.

## 체크포인트

- 보고서가 테스트 모델의 올바른 파라미터 수를 보여 줍니다.
- 파라미터를 편집하면 변경 카운터가 증가하고, 모델이 없는 경우에는 친절한 메시지가 표시됩니다.
- `cubism-versions.json`에는 테스트한 버전만 나열되어 있습니다.
