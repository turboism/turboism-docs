이 단계에서 Parameter Peek는 실제 플러그인이 됩니다. 명령을 등록하고, 메뉴에 넣고, 인사 메시지를 표시합니다. 아직 Cubism 데이터는 다루지 않습니다. 그 과정에서 플러그인 수명 주기, 액션과 메뉴, 선언된 권한, 현지화를 만나게 됩니다.

## 1. 진입점 작성

`src/main/java/com/example/parameterpeek/ParameterPeekPlugin.java`의 내용을 다음으로 교체합니다:

```java title="ParameterPeekPlugin.java"
package com.example.parameterpeek;

import dev.turboism.sdk.action.ActionRegistry;
import dev.turboism.sdk.menu.MenuRegistry;
import dev.turboism.sdk.plugin.PluginContext;
import dev.turboism.sdk.plugin.PluginLogger;
import dev.turboism.sdk.plugin.Registration;
import dev.turboism.sdk.plugin.TurboismPlugin;
import dev.turboism.sdk.ui.StatusNotification;
import dev.turboism.sdk.ui.UiHostCapabilityService;

public final class ParameterPeekPlugin implements TurboismPlugin {

    private PluginContext context;
    private PluginLogger logger;

    @Override
    public void init(final PluginContext context) throws Exception {
        this.context = context;
        this.logger = context.logger();
        logger.info("Parameter Peek initialized");
    }

    @Override
    public void enable() throws Exception {
        Registration action = context.actions().register(
                "parameterpeek.report",
                ActionRegistry.Action.of(
                        "parameterpeek.report",
                        context.localization().text("parameterpeek.action.report"),
                        ignored -> report()));
        context.disposableScope().register(action);

        Registration menu = context.menus().contribute(MenuRegistry.MenuContribution.of(
                context.localization().text("parameterpeek.menu"), "parameterpeek.report", 100));
        context.disposableScope().register(menu);

        logger.info("Parameter Peek enabled");
    }

    private void report() {
        final String message = context.localization().text("parameterpeek.hello");
        logger.info(message);
        context.services().find(UiHostCapabilityService.class).ifPresent(ui ->
                ui.notifyStatus(new StatusNotification("parameterpeek.report", "INFO", message)));
    }

    @Override
    public void disable() throws Exception {
        logger.info("Parameter Peek disabled");
    }

    @Override
    public void shutdown() throws Exception {
        logger.info("Parameter Peek shutdown");
        context = null;
    }
}
```

클래스는 `public`이어야 하고, `TurboismPlugin`(또는 그 하위 인터페이스)을 구현해야 하며, public 매개변수 없는 생성자가 있어야 합니다. 암시적 생성자로 충분합니다. Runtime이 클래스를 대신 생성하므로 `new ParameterPeekPlugin()`을 직접 호출해서는 안 됩니다.

### 핵심 메커니즘: 네 가지 수명 주기 메서드

| 메서드 | Runtime의 호출 시점 | 용도 |
| --- | --- | --- |
| `init(context)` | 권한 범위가 적용된 `PluginContext`와 함께 한 번 호출됩니다. | 컨텍스트를 보관하고 비공개 상태를 준비합니다. |
| `enable()` | 플러그인이 활성화될 때 호출됩니다. | 액션, 메뉴, 구독 및 기타 눈에 보이는 동작을 등록합니다. |
| `disable()` | 플러그인이 꺼질 때 호출됩니다. | 활성 동작을 중지합니다. |
| `shutdown()` | 비활성화가 마무리된 후 호출됩니다. | 비공개 리소스를 해제합니다. |

생성, `init` 또는 `enable`에서 예외가 발생하면 Runtime은 JAR 전체를 롤백합니다. `init`이 실패하면 `enable`은 실행되지 않습니다. 그래서 `enable()`이 등록을 수행하기에 알맞은 위치입니다. Runtime이 등록을 기대하는 곳이고, 실패가 안전하게 처리되는 곳이기 때문입니다.

규칙의 나머지 절반은 정리입니다. 받은 모든 `Registration`은 `AutoCloseable` 핸들입니다. 이를 `context.disposableScope().register(...)`에 전달하면 플러그인이 비활성화될 때 Runtime이 역순으로 닫습니다. 정리 코드를 작성하지 않았는데도 플러그인이 비활성화되면 명령과 메뉴 항목이 사라집니다. 스코프를 잊으면 등록이 플러그인보다 오래 남아 Runtime이 플러그인의 ClassLoader를 안전하게 해제하지 못할 수 있습니다. 여러 진입점과 핫 리로드를 포함한 전체 모델은 [수명 주기 및 정리](/docs/build-a-plugin/key-mechanisms/lifecycle-and-cleanup)를 읽어 보세요.

### 핵심 메커니즘: 액션과 메뉴는 별개입니다

동작과 배치는 따로 등록합니다:

- **액션**에는 안정적인 ID(`parameterpeek.report`), 레이블, 핸들러가 있습니다. 액션은 동작의 단위이며 키보드 단축키, 메뉴, 도구 모음, 컨텍스트 메뉴에 바인딩할 수 있습니다.
- **메뉴 기여**는 슬래시로 구분된 메뉴 경로를 액션 ID와 순서 번호에 바인딩합니다.

액션 ID는 안정적인 식별자로 취급하여 릴리스 간에 일정하게 유지하세요. 이름을 바꾸면 다른 액션이 됩니다. 여기서 메뉴 경로 `Tools/Parameter Peek`는 현지화 카탈로그에서 가져오므로 메뉴 텍스트를 번역할 수 있습니다. 도구 모음, 컨텍스트 메뉴, 설정 페이지는 [플러그인 인터페이스](/docs/build-a-plugin/plugin-interfaces)를 참고하세요.

핸들러는 상태 표시줄 서비스가 있다고 가정하지 않고 `context.services().find(...)`를 사용합니다. `find`는 `Optional`을 반환하므로 호스트가 해당 서비스를 제공하지 않아도 플러그인은 조용히 기능을 축소해 동작합니다. 이것이 왜 중요한지는 [권한과 가용성](/docs/build-a-plugin/key-mechanisms/permissions-and-availability)에서 설명합니다.

## 2. 텍스트 카탈로그 추가

사용자에게 보이는 텍스트는 Java 문자열이 아니라 항상 카탈로그에 둡니다. `src/main/resources/META-INF/turboism/i18n/messages.properties`를 다음으로 교체합니다:

```properties title="messages.properties"
plugin.name=Parameter Peek
plugin.description=Reports how many parameters the active model has and how often they change.
parameterpeek.action.report=Parameter Peek: Report
parameterpeek.menu=Tools/Parameter Peek
parameterpeek.hello=Hello from Parameter Peek!
```

그런 다음 같은 내용을 옆에 있는 `messages_en.properties`에 복사합니다. 디스크립터는 어떤 카탈로그가 존재하는지 선언하며(`"locales": ["en"]`), Runtime은 선언된 모든 카탈로그가 JAR에 있어야 한다고 요구합니다. 기본 `messages.properties`는 로캘에서 키가 없을 때 항상 최종 폴백입니다. 나중에 언어를 추가하려면 `messages_<locale>.properties`를 추가하고 로캘을 목록에 넣으세요. 로캘 ID는 [플러그인 매니페스트 및 패키징](/docs/build-a-plugin/manifest)을 참고하세요.

## 3. 권한 선언

`src/main/resources/META-INF/turboism/plugin.json`을 엽니다. 템플릿은 자체 샘플을 위한 권한(`publish`, `subscribe`, `register`)을 선언하고 있습니다. `description`, `category`, `permissions`, `lifecycle` 부분을 Parameter Peek를 설명하도록 교체합니다:

```json title="plugin.json"
{
  "format": "turboism.plugin.meta",
  "schemaVersion": 3,
  "id": "com.example.parameterpeek",
  "name": "Parameter Peek",
  "version": "0.1.0",
  "description": "Reports how many parameters the active model has and how often they change.",
  "category": "analysis",
  "tags": ["example", "parameters"],
  "entrypoints": [
    "com.example.parameterpeek.ParameterPeekPlugin"
  ],
  "turboismApi": "[0.67.0,1.0.0)",
  "authors": [
    { "name": "Your Name" }
  ],
  "license": "MIT",
  "website": "https://example.com/parameter-peek",
  "resources": [],
  "i18n": {
    "baseName": "META-INF/turboism/i18n/messages",
    "locales": ["en"]
  },
  "dependencies": [],
  "permissions": [
    { "id": "turboism.action.register", "scope": "application", "reason": "Registers the Parameter Peek report action." },
    { "id": "turboism.ui.menu.contribute", "scope": "application", "reason": "Adds the report command to the Tools menu." },
    { "id": "turboism.ui.status.notify", "scope": "application", "reason": "Shows the report in the status bar." }
  ],
  "capabilities": [],
  "lifecycle": {
    "hotReload": true
  },
  "environment": {
    "requiresCubism": true,
    "ui": "none"
  }
}
```

`authors`, `license`, `website` 값은 자신의 프로젝트에 맞게 사실대로 유지하세요. 사용자에게 표시되는 값입니다. 플러그인을 공유하기 전에 `example`이 들어간 항목은 모두 바꾸세요.

### 핵심 메커니즘: 선언한 것만 얻습니다

각 권한은 넘고자 하는 하나의 위험 경계를 지정하며, 플러그인을 검토하는 사람에게 표시되는 `reason`을 가집니다:

| 권한 | 이 플러그인에 필요한 이유 |
| --- | --- |
| `turboism.action.register` | `context.actions().register(...)` |
| `turboism.ui.menu.contribute` | `context.menus().contribute(...)` |
| `turboism.ui.status.notify` | `ui.notifyStatus(...)` |

선언하지 않은 접근은 조용히 허용되지 않고 호출 시점에 거부되므로, 권한이 빠지면 명령을 처음 실행할 때 오류로 나타납니다. 최소한만 선언하고 더 큰 플러그인의 권한을 복사하지 마세요. 권한 ID 목록은 SDK의 `PermissionIds` 클래스이며 [SDK HTML API 레퍼런스](https://turboism.dev/sdk/dev/turboism/sdk/permission/PermissionIds.html)에 문서화되어 있습니다. 또한 `category`는 `analysis`처럼 소문자 kebab-case 토큰으로 유지하세요. 검토된 퍼스트 파티 카테고리는 [플러그인 매니페스트 및 패키징](/docs/build-a-plugin/manifest#카테고리와-태그)에 나열되어 있습니다.

여기서 `lifecycle.hotReload`가 `true`인 이유는 Parameter Peek가 일반 SDK 서비스만 사용하고 disposable 스코프(`disposableScope()`)를 통해 정리하기 때문입니다. 바이트코드 변환기나 네이티브 훅을 등록하는 플러그인은 `false`를 선언해야 합니다.

## 4. 빌드

```bash
./gradlew build
```

빌드가 import 누락으로 실패하면 import를 포함하여 파일 전체를 교체했는지 확인하세요. 템플릿에 있던 `HelloEvent`나 `hello.action.label`에 대한 참조가 남아 있는 것이 일반적인 원인입니다.

## 체크포인트

- 프로젝트가 빌드되고 `build/libs/parameterpeek-turboism-plugin-0.1.0.jar`가 존재합니다.
- `plugin.json`은 권한을 정확히 세 개 선언하며, 각 권한은 가리킬 수 있는 코드 줄에서 사용됩니다.
- `messages.properties`와 `messages_en.properties` 모두 동일한 다섯 개의 키를 포함합니다.
