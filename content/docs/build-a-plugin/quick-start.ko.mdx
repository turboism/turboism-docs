title: 개발자 빠른 시작
description: 공개 SDK를 사용하여 최소한의 Java 17 Turboism 플러그인을 빌드합니다.
---

Turboism은 공식 독립 프로젝트 템플릿과 스캐폴딩 도구를 제공합니다. 템플릿에서 독립 저장소를 생성하고 자동 설정 스크립트를 실행하여 일치하는 SDK 및 어노테이션 프로세서를 내려받아 개발할 수 있습니다.


이 예제는 Stable 0.67.4를 기준으로 합니다. 설정 스크립트는 기본적으로 stable 채널을 해석하고 해당 릴리스에서 `turboism-sdk-<version>.jar`와 `turboism-event-processor-<version>.jar`를 다운로드합니다. `gradle.properties`(`turboismSdkVersion`)와 다운로드한 파일명에서 컴파일에 사용하는 SDK 버전을 확인하세요. `--channel beta` 또는 `--version <version>`은 의도적으로 다른 릴리스를 대상으로 할 때만 사용하세요.

## 1. 공식 독립 템플릿 사용 (권장)

GitHub의 **Use this template**을 통해 [`turboism/turboism-plugin-template`](https://github.com/turboism/turboism-plugin-template) 저장소를 기반으로 생성하거나 직접 복제합니다:

```bash
git clone https://github.com/turboism/turboism-plugin-template.git my-plugin
cd my-plugin
```

스캐폴딩 설정 스크립트를 실행합니다(공식 릴리스 피드에서 일치하는 버전의 SDK와 이벤트 어노테이션 프로세서를 다운로드하고 SHA-256을 검증합니다):

```bash
# Linux / macOS
./scripts/setup.sh --channel stable

# Windows (PowerShell)
.\scripts\setup.ps1 -Channel stable
```

터미널의 대화형 프롬프트에 따라 플러그인 ID(예: `com.example.myplugin`), 표시 이름, 패키지 이름, 작성자 정보를 입력합니다. 스크립트가 Java 패키지와 클래스 이름을 재구성하고 `libs/`에 종속성을 구성합니다.

## 2. 프로젝트 구조 및 빌드 구성

독립 템플릿의 디렉터리 레이아웃:

```text
my-plugin/
├── gradlew
├── gradlew.bat
├── build.gradle.kts
├── libs/
│   ├── turboism-sdk-*.jar
│   └── turboism-event-processor-*.jar
├── src/main/java/com/example/myplugin/MyPlugin.java
├── src/main/resources/META-INF/turboism/plugin.json
└── src/main/resources/META-INF/turboism/cubism-versions.json
```

설정 스크립트가 JAR를 `libs/`에 배치했을 때의 `build.gradle.kts` 구성(JAR가 없으면 템플릿은 `turboismSdkVersion`을 사용해 `mavenLocal()`에서 `dev.turboism:sdk`와 `dev.turboism:event-processor`를 해석합니다):

```kotlin
plugins {
    `java-library`
}

java {
    sourceCompatibility = JavaVersion.VERSION_17
    targetCompatibility = JavaVersion.VERSION_17
}

val sdkJars = fileTree("libs") { include("turboism-sdk-*.jar") }
val eventProcessorJars = fileTree("libs") { include("turboism-event-processor-*.jar") }

dependencies {
    compileOnly(sdkJars)
    if (!eventProcessorJars.isEmpty) {
        annotationProcessor(eventProcessorJars)
        annotationProcessor(sdkJars)
    }
}
```

`compileOnly`는 의도된 것입니다: Runtime이 실행 시점에 SDK를 제공합니다. 플러그인 JAR에 `dev/turboism/sdk/**` 클래스를 포함하지 마십시오.

Runtime, Bootstrap, `com.live2d.*` 내부 클래스, 다른 플러그인의 비공개 구현 패키지, 리플렉션 브리지, 네이티브 핸들에 의존하지 마십시오.

## 3. 진입점 및 이벤트 수신 구현

```java
package com.example.myplugin;

import dev.turboism.sdk.event.SubscribeEvent;
import dev.turboism.sdk.cubism.event.ParameterValueEvent;
import dev.turboism.sdk.plugin.PluginContext;
import dev.turboism.sdk.plugin.TurboismPlugin;

public final class MyPlugin implements TurboismPlugin {
    private PluginContext context;

    @Override
    public void init(final PluginContext context) {
        this.context = java.util.Objects.requireNonNull(context, "context");
        context.logger().info("MyPlugin initialized");
    }

    @Override
    public void enable() {
        context.logger().info("MyPlugin enabled");
    }

    @SubscribeEvent
    public void onParameterChanged(final ParameterValueEvent.On event) {
        context.logger().info("Parameter changed: " + event.parameter().id());
    }

    @Override
    public void disable() {
        context.logger().info("MyPlugin disabled");
    }

    @Override
    public void shutdown() {
        context.logger().info("MyPlugin shutdown");
        context = null;
    }
}
```

- 클래스는 public이어야 하며 `TurboismPlugin` 또는 그 하위 인터페이스를 구현하고 public 매개변수 없는 생성자를 제공해야 합니다.
- `@SubscribeEvent` 어노테이션을 사용하여 이벤트 수신 메서드를 선언할 수 있으며, 컴파일 시점에 `turboism-event-processor`가 인덱스를 생성합니다.

`@CubismEditor`는 API 버전 제약을 나타내며 권한이나 기능 가용성을 보장하지 않습니다. 플러그인 지원 버전은 별도의 `META-INF/turboism/cubism-versions.json` 파일에 선언하세요([매니페스트](./manifest) 참고).

## 4. 플러그인 디스크립터 추가

`src/main/resources/META-INF/turboism/plugin.json` 편집:

```json
{
  "format": "turboism.plugin.meta",
  "schemaVersion": 3,
  "id": "com.example.myplugin",
  "name": "My Plugin",
  "version": "0.1.0",
  "description": "Minimal Turboism plugin lifecycle example.",
  "category": "workflow",
  "tags": ["example"],
  "entrypoints": [
    "com.example.myplugin.MyPlugin"
  ],
  "turboismApi": "[0.67.0,1.0.0)",
  "authors": [
    { "name": "Example Author" }
  ],
  "license": "MIT",
  "website": "https://example.org/my-plugin",
  "resources": [],
  "i18n": {
    "baseName": "META-INF/turboism/i18n/messages",
    "locales": []
  },
  "dependencies": [],
  "permissions": [
    { "id": "turboism.event.subscribe", "scope": "application", "reason": "Subscribe to parameter observations." },
    { "id": "turboism.cubism.model.observe", "scope": "application", "reason": "Observe parameter value changes." }
  ],
  "capabilities": [],
  "lifecycle": {
    "hotReload": true
  },
  "environment": {
    "requiresCubism": true,
    "ui": "none"
  }
}
```

- `"lifecycle": { "hotReload": true }`는 플러그인이 핫 리로드를 지원함을 선언하여, Cubism을 재시작하지 않고도 활성화, 비활성화 및 업데이트가 즉시 적용됩니다.
- `turboismApi`는 플러그인 SDK API 범위입니다. `[0.67.0,1.0.0)`은 0.67.0 이상 1.0.0 미만의 모든 프레임워크 API를 허용합니다. 이후 릴리스에서 추가된 SDK 멤버를 사용한다면 하한을 올리세요. 레거시 `[0.1.0,0.2.0)` 디스크립터는 거부됩니다.
- 권한, 리소스, 다국어 설정의 세부 사항은 [플러그인 Manifest 및 패키징](./manifest)을 참고하십시오.

## 5. 빌드 및 검증

```bash
./gradlew build
```

빌드 산출물 위치:

```text
build/libs/myplugin-turboism-plugin-0.1.0.jar
```

## 6. 설치 및 디버깅

1. Cubism Editor를 실행하고 **Turboism** 메뉴를 엽니다.
2. **플러그인 관리…** → **JAR에서 설치…**를 선택하고 빌드된 `.jar` 파일을 선택합니다.
3. 핫 리로드를 지원하는 플러그인은 즉시 로드되어 활성화됩니다. 그 외 플러그인은 Cubism 재시작 후 적용됩니다.
4. 로컬 디버깅 시 `<turboism.home>/plugins/` 디렉터리에 직접 JAR을 복사할 수도 있습니다.

## 고급: 소스 트리 내 모듈 개발

Turboism 핵심 기여자는 저장소 내에서 직접 `plugins/<name>` 모듈을 추가할 수 있습니다:

```bash
# settings.gradle.kts에 추가
include("plugins:my-plugin")

# 빌드 및 검증
./gradlew :plugins:my-plugin:test :plugins:my-plugin:jar validatePluginMeta --console=plain
```
