description: 사용할 수 없는 기능에 대해 안전하게 실패하는, 수명 주기에 안전한 SDK 전용 Turboism 플러그인을 설계합니다.
---

오래 유지되는 Turboism 플러그인은 하나의 사용자 가시적 목적을 가지고 SDK에만 의존하며, 호스트 통합, 스케줄링, 안전 및 정리를 런타임이 담당하도록 합니다.

## 경계를 작게 유지하기

```text
Plugin -> SDK -> Runtime policy -> versioned Adapter/Provider -> Cubism/Editor
```

런타임 관심사에 대한 플러그인 로컬 추상화를 추가하지 마세요. 구성, 저장소, 작업, 이벤트, UI, 사용자 파일 및 Cubism 접근에는 `PluginContext` 서비스를 재사용하세요.

피해야 할 것:

- 런타임이나 `com.live2d.*`에 대한 직접 의존;
- 리플렉션과 원시 호스트 오브젝트;
- 관리되지 않는 실행기, 스레드 및 타이머;
- Swing/AWT 호스트 위젯 탐색;
- 전역 가변 레지스트리;
- 추측성 팩터리와 확장 계층.

## 수명 주기 계획하기

네 가지 실제 수명 주기 메서드를 사용하세요:

1. `init` — 컨텍스트를 보관하고, 스키마를 등록하고, 플러그인 전용 상태를 만듭니다.
2. `enable` — 액션, 이벤트, UI 및 작업을 등록합니다.
3. `disable` — 핫 언로드를 가정하지 않고 활성 동작을 중지합니다.
4. `shutdown` — 런타임 수명 주기가 정리된 후 플러그인 전용 상태를 해제합니다.

의도적으로 더 일찍 닫는 경우가 아니면 닫을 수 있는 모든 등록이나 핸들을 `DisposableScope`에 넣으세요.

## 권한과 가용성 분리하기

권한은 플러그인이 위험 경계를 넘을 수 있는지를 나타냅니다. 기능은 런타임과 활성 호스트 버전이 그 작업을 수행할 수 있는지를 나타냅니다.

두 경로를 모두 설계하세요:

- 지원되는 프로바이더를 통한 성공;
- 명시적인 사용 불가, 지원되지 않음, 오래됨, 거부됨, 시간 초과, 백프레셔 또는 거부됨 결과.

권한을 프로바이더가 존재한다는 증거로 절대 취급하지 마세요.

## Editor 소유권을 중심으로 쓰기 설계하기

Editor에 연결된 모델에서 Editor 작성 상태가 쓰기의 진실 원천입니다. 안전한 쓰기에는 다음이 필요할 수 있습니다:

- 검증;
- 호스트 스레드 디스패치;
- 트랜잭션과 Undo;
- 변경 상태와 새로 고침 처리;
- 롤백 또는 명시적인 부분 실패;
- 세대/오래된 대상 거부;
- 영속성이 주장되는 경우 저장/재열기 검증.

Cubism Core를 두 번째 독립 작성 상태로 변경하거나 평가 전용 변경에 대해 Undo 항목을 합성하지 마세요.

## 경계에서 변경 불가능한 값 사용하기

이벤트, UI 디스크립터, 스냅샷, 선택, 구성 값 및 작업 요청은 변경 불가능한 SDK 또는 플러그인 소유 값이어야 합니다.

다음을 유출하지 마세요:

- 호스트 오브젝트;
- 호스트 UI 컨트롤;
- 네이티브 핸들;
- 호스트 ClassLoader;
- 변경 가능한 Cubism 소유 배열;
- 제한 없는 파일 시스템 경로.

## 하나의 액션, 하나의 기여를 선호하기

사용자 동작은 액션으로 등록한 다음 메뉴, 도구 모음, 패널 또는 컨텍스트 메뉴 기여를 그 액션 ID에 바인딩하세요. 이렇게 하면 호스트 UI 없이도 동작을 테스트할 수 있습니다.

## 가장 작은 실제 계약 테스트하기

수명 주기 로깅만 하는 플러그인에는 생성자/수명 주기 테스트가 필요합니다. 등록이 있는 플러그인은 기록/가짜 `PluginContext`를 사용해 다음을 검증해야 합니다:

- 요청한 권한과 사용할 수 없는 경로;
- 등록과 스코프 정리;
- 사용 안 함/종료 동작;
- 변경 불가능한 이벤트와 DTO 동작;
- 구성 마이그레이션과 리비전 충돌;
- 해당하는 경우 작업 취소 또는 거부.

호스트 버전 주장에는 프로젝트의 고위험 검증 워크플로가 필요하며, 가짜 테스트는 실제 호스트 준비 상태를 확립하지 않습니다.

## 설계 체크리스트

- [ ] 플러그인에 하나의 명확한 목적이 있습니다.
- [ ] 프로덕션 코드는 SDK에만 의존합니다.
- [ ] 플러그인 디스크립터가 지원되는 스키마 버전, 정확한 진입점, 리소스, 종속성 및 최소 권한을 선언합니다.
- [ ] 등록과 핸들이 닫을 수 있고 스코프에 속합니다.
- [ ] 사용할 수 없는 프로바이더는 유용한 진단과 함께 안전하게 실패합니다.
- [ ] 플러그인이 주장하는 모든 로캘에 현지화 카탈로그가 존재합니다.
- [ ] 구성, 저장소 및 사용자 파일이 올바른 서비스를 사용합니다.
- [ ] 관리되지 않는 스레드, 실행기, 타이머, 호스트 오브젝트 또는 리플렉션 브리지가 없습니다.
- [ ] 쓰기가 Editor 소유권과 Undo 의미를 보존합니다.
- [ ] 가장 작은 집중 테스트가 실제 계약을 검증합니다.
