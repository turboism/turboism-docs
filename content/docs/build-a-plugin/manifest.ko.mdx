---
title: 플러그인 매니페스트 및 패키징
description: 스키마 버전 2, 3 및 4의 플러그인 디스크립터를 정의하고 빌드한 JAR을 배포합니다.
---

모든 Turboism 플러그인 JAR에는 다음 위치에 디스크립터가 정확히 하나 포함됩니다:

```text
META-INF/turboism/plugin.json
```

디스크립터는 `"format": "turboism.plugin.meta"`와 `schemaVersion`을 선언합니다. 런타임은 스키마 버전 **2**, **3**, **4**를 허용하고 일치하는 계약에 대해 엄격하게 검증하며, 디스크립터를 자동으로 업그레이드하지 않습니다.

| 버전 | 계약 |
| --- | --- |
| 2 | 기본 수명 주기, 진입점, API 범위, 종속성, 권한, 리소스 및 현지화. |
| 3 | 필수 `category` 필드와 선택적 `tags`를 추가합니다(v3은 기본 제공 플러그인이 사용하는 버전입니다). |
| 4 | 선언된 플러그인 간 이벤트 계약인 `eventExports`와 `eventImports`를 추가합니다. |

스키마 버전 1은 로드되지 않습니다. 알 수 없는 필드는 무시하지 않고 거부됩니다.

## 매니페스트 예제

```json
{
  "format": "turboism.plugin.meta",
  "schemaVersion": 3,
  "id": "dev.example.plugin.hello",
  "name": "Hello Plugin",
  "version": "0.1.0",
  "description": "Minimal Turboism plugin lifecycle example.",
  "category": "workflow",
  "tags": ["example", "lifecycle"],
  "entrypoints": [
    "dev.example.plugin.HelloPlugin"
  ],
  "turboismApi": "[0.1.0,0.2.0)",
  "authors": [
    { "name": "Example Author" }
  ],
  "license": "MIT",
  "website": "https://example.org/hello-plugin",
  "resources": [],
  "i18n": {
    "baseName": "META-INF/turboism/i18n/messages",
    "locales": []
  },
  "dependencies": [],
  "permissions": [],
  "capabilities": [],
  "environment": {
    "requiresCubism": false,
    "ui": "none"
  }
}
```

필수 필드는 `id`, `name`, `version`, `entrypoints`, `turboismApi`, `authors`, `website`, `resources`, `i18n`이며, 스키마 3은 여기에 `category`를 추가로 요구합니다.

## 진입점 규칙

각 진입점은 다음을 충족해야 합니다:

- 같은 플러그인 JAR에 존재합니다;
- public입니다;
- `TurboismPlugin` 또는 그 하위 인터페이스를 구현합니다;
- public 무인수 생성자를 노출합니다.

여러 진입점은 하나의 플러그인 정체성, 디스크립터, ClassLoader, `PluginContext`, `DisposableScope`, 권한 집합, 구성 네임스페이스, 저장소 네임스페이스, 리소스 및 현지화 선언을 공유합니다.

```text
construct/init/enable: manifest order
disable/shutdown:       reverse manifest order
```

생성, 초기화 또는 사용 단계에서 실패하면 JAR 전체가 롤백됩니다.

## 카테고리와 태그

`category`는 2–32자 길이의 소문자 케밥 케이스 토큰이어야 합니다. 검토된 기본 제공 카테고리는 `modeling`, `workflow`, `appearance`, `analysis`, `performance`, `integration`, `system` 및 `development`입니다. 형식은 올바르지만 등록되지 않은 카테고리도 로드되며 `other`로 표시되고 구조화된 `PLUGIN_CATEGORY_UNKNOWN` 진단을 발생시킵니다.

`tags`는 선택적이며 최대 12개의 2–32자 소문자 케밥 케이스 토큰을 담고, 어떤 권한이나 기능도 수반하지 않습니다.

## 종속성

```json
{
  "id": "dev.example.plugin.base",
  "version": "[1.0.0,2.0.0)",
  "type": "required",
  "ordering": "after",
  "reason": "Uses the base plugin contract."
}
```

- `type`은 `required` 또는 `optional`입니다.
- `ordering`은 `none`, `before` 또는 `after`입니다.
- 종속성 ID는 역도메인 문법을 사용합니다.
- 버전 범위는 Turboism 버전 범위 문법을 사용합니다.

종속성 레코드는 해석과 순서를 제어합니다. 다른 플러그인의 비공개 구현 패키지를 공개 Java 종속성으로 만들지는 않습니다.

## 권한

각 권한 레코드는 알려진 ID, `application` 또는 `user` 스코프, 그리고 비어 있지 않은 사유를 포함합니다.

```json
{
  "id": "turboism.action.register",
  "scope": "application",
  "reason": "Registers the Hello action."
}
```

플러그인이 호출하는 SDK 서비스에 필요한 권한만 선언하세요. 권한은 프로바이더 가용성을 보장하지 않으며 작업 검증을 우회하지 않습니다.

## 리소스와 현지화

리소스 루트는 `/`로 끝나는 정규화된 상대 접두사입니다:

```json
"resources": ["icons/"],
"i18n": {
  "baseName": "META-INF/turboism/i18n/messages",
  "locales": ["base", "en", "zh-Hans"]
}
```

그러면 JAR에 다음이 포함되어야 합니다:

```text
icons/hello.png
META-INF/turboism/i18n/messages.properties
META-INF/turboism/i18n/messages_en.properties
META-INF/turboism/i18n/messages_zh_Hans.properties
```

선언된 루트와 카탈로그가 존재해야 합니다. 일반 비클래스 리소스는 선언된 루트에 속해야 합니다. 경로 순회, 절대 경로, 백슬래시, 빈 세그먼트 및 선언되지 않은 리소스는 거부됩니다.

지원되는 런타임 로캘은 `en`, `ja`, `ko`, `zh-Hans`, `zh-Hant`와 `base` 번들입니다. 매니페스트 로캘 ID는 스크립트 형식(`zh-Hans`)을 사용하고, 리소스 번들 파일 이름은 Java 밑줄 형식(`messages_zh_Hans.properties`)을 사용합니다.

## 플러그인 간 이벤트 계약(스키마 4)

스키마 4에서는 플러그인이 자신이 소유하고 소비하는 공개 이벤트 타입을 선언할 수 있으므로, 런타임이 ClassLoader 위임 없이 이를 해석할 수 있습니다:

```json
"eventExports": [
  {
    "id": "dev.example.event.hello",
    "contractVersion": "1.0.0",
    "eventType": "dev.example.api.HelloEvent",
    "abiSha256": "<sha256 of the event type bytes>"
  }
],
"eventImports": [
  {
    "provider": "dev.example.plugin.base",
    "eventId": "dev.example.event.base-status",
    "contractVersion": "1.0.0",
    "eventType": "dev.example.api.BaseStatusEvent",
    "abiSha256": "<sha256 of the event type bytes>"
  }
]
```

`eventImports` 항목은 `"required": true`를 함께 지정해 해당 프로바이더 계약이 허용되어야 함을 요구할 수도 있습니다. 런타임은 모든 항목에 대해 선언된 ABI 다이제스트를 검증하고, 플러그인 내 중복 내보내기 ID나 이벤트 타입을 거부하며, 허용된 프로바이더 계약으로 해석되지 않는 가져오기를 거부합니다.

플러그인 ID는 점이 하나 이상 있는 역도메인 문법(`dev.example.plugin.hello`)을 사용하고, 이벤트 ID는 소문자 점/대시 토큰 형식을 사용합니다.

## 빌드 및 검증

저장소 내 플러그인 모듈의 경우:

```bash
./gradlew :plugins:hello:test :plugins:hello:jar validatePluginMeta \
  --no-daemon --console=plain
```

저장소는 Java 17을 사용하고 모듈 빌드 결과를 다음 위치에 기록합니다:

```text
build/worktree/<worktreeId>/<module>/libs/
```

`libs/`의 JAR이 릴리스 파일입니다. 래퍼 아카이브와 별도의 패키징 단계가 없습니다.

## 엄격한 JAR 검증

JAR 자체가 설치 파일입니다. 런타임은 선택한 JAR을 신뢰할 수 없는 로컬 입력으로 취급하고 다음을 검증합니다:

- 소스 체인에 심볼릭 링크가 없고 일반 파일이며, 제한된 원시 크기, 항목별 크기, 총 확장 크기, 항목 수 및 압축률 한도 이내일 것;
- `META-INF/turboism/plugin.json`이 정확히 하나일 것;
- 디스크립터 ID, 버전 및 API 범위의 일관성;
- 복사된 SDK, 런타임, 테스트, 테스트 프레임워크 또는 Live2D 클래스가 없을 것;
- 네이티브 바이너리나 설치 프로그램 페이로드가 없을 것;
- 중첩 JAR이 없을 것;
- 선언된 진입점, 리소스 루트 및 i18n 카탈로그가 존재할 것;
- 선언되지 않은 일반 리소스가 없을 것.

관리형 설치는 검증된 JAR을 스테이징하고 Cubism 재시작 후에 적용합니다. 임의의 ZIP이나 JAR 이름을 바꿔 플러그인을 만들지 마세요. 항상 Gradle 빌드가 생성한 JAR을 배포하세요.
