## 项目边界

Turboism 是基于 Java 的集成与插件框架。产品文档在运行时必须独立于应用、学习和插件项目。不要把修改宿主安装作为开发或测试的捷径。在相关源码和测试确认之前，请将每种行为视为与版本和 capability 有关。

## 架构与扩展路径

框架有三条不同的路径：

1. **Java 插件**是在进程内运行的插件，具有 Java SDK 生命周期、manifest、权限和服务。
2. **GraalJS 脚本**是受限脚本，由 Java 插件通过 `PluginContext.scripts()` 发现，并通过 `ScriptService.run` 显式运行；仅被发现不会执行脚本。
3. **MCP** 是第一方 Preview 插件，向可信本地外部客户端提供经过认证的 loopback Streamable HTTP。

ACP 仅与 fx 在内部使用，不是第四种扩展路径。代码库以 Java 17 为目标。不要因为所需 capability 看似相邻，就用一条路径替代另一条。

## 贡献流程

保持改动聚焦，行为改变时更新或添加有针对性的测试，并从适用检出运行仓库记录的 Gradle 检查：

```bash
./gradlew focusedTest
./gradlew devCheck
./gradlew checkCompletedCommit
```

先运行最小的相关测试，再运行与改动相称的更广泛检查。如果命令、任务、模块或契约不存在，请先从源码或构建配置确认，再提出替代方案。
