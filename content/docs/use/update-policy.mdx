---
title: Update Policy
description: Replace Preview plugins safely and understand which automatic update capabilities do not exist yet.
---

Turboism currently has local package replacement, not a production automatic update system.

## Plugin replacement today

Installing a newer `.tplugin` with the same plugin ID stages a replacement intent. It applies after Cubism restarts.

1. Back up the current plugin package.
2. Back up persistent `config/<pluginId>/` and `data/<pluginId>/` content when it matters.
3. Install the newer `.tplugin` through plugin management.
4. Restart Cubism.
5. Verify version, lifecycle state, configuration migration, and logs.
6. If the replacement fails, stop Turboism and restore or reinstall the known-good package.

This workflow does not retain historical generations or provide a complete transactional rollback UI.

## Framework Preview updates

The isolated Developer Preview directory is relocatable and removable. For a newer Preview build:

1. keep the previous Preview directory until the new build passes startup checks;
2. use a disposable project copy;
3. preserve the previous Turboism home or create a separate new home when testing migration behavior;
4. verify Java Agent startup, plugin discovery, host capability status, and clean shutdown;
5. remove the old Preview only after the new one is accepted.

Do not overwrite or rewrite Cubism installation files as an update mechanism.

## Compatibility expectations

- New SDK APIs are Preview by default.
- API presence does not guarantee every Cubism version has a Provider.
- Host-sensitive operations can remain unavailable on unsupported or unverified versions.
- Plugin authors should use the declared Turboism API range and test unavailable behavior.
- The generated API reference tracks current development source, not a final Stable release line.

## Not currently available

- online update discovery and downloads;
- marketplace channels;
- publisher signatures and revocation;
- retained immutable package generations;
- automatic repair, rollback, or recovery;
- system-level framework installer updates;
- a published Stable compatibility matrix.
