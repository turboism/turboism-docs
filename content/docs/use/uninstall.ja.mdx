---
title: アンインストール
description: Turboism を専用のアンインストーラーで削除し、個人設定を保持するか選択する。
---

使用中の build をインストールしたインストーラーが生成したアンインストーラーを使用してください。Turboism または Cubism が実行中の間は file を削除しないでください。

## インストーラーのアンインストーラーを使う

- **Windows、`.exe` インストール** — Turboism home ディレクトリの `uninstall.exe` を実行します。
- **Windows、`.jar` インストール** — 次を実行します。

  ```text
  java -jar <home>\Uninstaller\uninstaller.jar
  ```

- **macOS、`.jar` インストール** — home ディレクトリの `uninstall.command` をダブルクリックするか、ターミナルで実行します。

その後:

1. Turboism と Cubism を通常どおり終了します。
2. 対応するアンインストーラーを起動します。
3. その確認手順に従います。
4. 表示されたら、configuration を保持するか選択します。再インストールする可能性がある、または同じ preference が後で必要なら保持します。不要であり重要な内容を保存済みの場合にだけ削除してください。
5. 完了後、削除したインストールを通じて Cubism が起動しなくなったことを確認します。

## 削除されるものと保持されるもの

- アンインストーラーは、インストーラーが所有する file に加え、ランタイムの `logs`、`state`、`cache` データを削除します。
- `config.json` は、削除を選択した場合にのみ削除されます。NSIS と Java の両方のアンインストーラーは、既定でこれを保持します。
- 不明な file と third-party plugin JAR は保持されます。アンインストーラーは、自身のものと特定できない material を削除しないためです。
- `data/<pluginId>/` 配下の plugin データが黙って破棄されることはありません。

アンインストール後に残った Turboism home を確認し、必要なものを backup してください。無関係な host file や project を削除する手段としてアンインストールを使わないでください。

## ランチャー連携

公式の Cubism 起動 BAT との連携を有効にしていた場合、削除時にその連携はハッシュで保護されたバックアップから復元されます。その後で管理対象ファイルが編集されていた場合、クリーンアップは競合を報告し、変更を上書きせずに state とバックアップを保持します。

## アンインストール前後

インストールを置き換える前に[更新ポリシー](./update-policy)を読んでください。更新またはモード変更に失敗した場合は、以前の build を安全に復元できると仮定せず、まず[ダウングレードと復旧](./downgrade-recovery)を確認します。
