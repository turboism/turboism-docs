---
title: 更新ポリシー
description: プラグインを置換し、インストーラーの再実行でフレームワークを更新する方法と、まだ存在しない自動更新機能について理解する。
---

Turboism に現在あるのは、ローカル JAR replacement と手動によるインストーラーの再実行であり、本番用の automatic update system ではありません。

## 現在のプラグイン置換

同じ plugin ID を持つ新しいプラグイン JAR をインストールすると、replacement intent がステージングされます。Cubism の再起動後に適用されます。

1. 現在の plugin JAR を backup します。
2. 重要な場合は、persistent `config/<pluginId>/` と `data/<pluginId>/` の内容を backup します。
3. plugin management を通じて新しい JAR をインストールします。
4. Cubism を再起動します。
5. version、lifecycle state、configuration migration、logs を確認します。

適用に失敗した場合、private backup から以前の plugin file が復元されます。この workflow は historical generation を保持せず、完全なユーザー向け修復・ロールバック・purge UI も提供しません。

## フレームワークのインストーラー更新

新しいフレームワークバージョンは、インストーラー artifact を再実行してインストールします。

1. そのビルドを提供した release または preview チャネルから、新しい `TurboismInstaller-<version>.exe`（Windows）または `TurboismInstaller-<version>.jar`（Windows/macOS）を入手します。
2. `config.json` と、重要な persistent プラグインの `config/`・`data/` の内容を backup します。
3. 新しいインストーラーを実行し、同じ Turboism home ディレクトリを対象にします。
4. 更新の一部としてプラグイン選択（Lite/Full）を再実行します。
5. 更新後に startup、plugin discovery、host capability status、logs を確認します。

インストーラーを再実行すると、同じ home と選択が更新され、無関係な設定を盲目的に上書きすることはありません。自動オンラインアップデーターも署名済みの公開ダウンロードチャネルもまだないため、インストーラーの更新は手動での再実行です。update の手段として Cubism installation file を上書きまたは書き換えないでください。

## 互換性に関する期待値

- 新しい SDK API はデフォルトで Preview です。
- API が存在しても、すべての Cubism version に Provider があるとは限りません。
- host-sensitive operation は、未サポートまたは未検証の version では利用できないままになることがあります。
- plugin author は宣言された Turboism API range を使用し、unavailable behavior をテストすべきです。
- generated API reference は現在の development source を追跡するもので、最終的な Stable release line ではありません。

## 現在利用できないもの

- 本番向け online update discovery と download。
- marketplace channel。
- publisher signature と revocation。
- retained immutable JAR generation。
- 完全なユーザー向け修復・ロールバック・リカバリ UI。
- 自動のシステムレベルインストーラー更新。
- 公開された Stable compatibility matrix。

組み込みの Official Directory client と UI は存在しますが、本番アクティベーションは未準備です。署名済み endpoint と key の準備は不完全です。
