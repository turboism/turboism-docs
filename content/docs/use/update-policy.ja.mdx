Turboism は 3 つのチャンネルで製品バージョンを公開し、機械可読なリリースフィードを通じて各パッケージをミラーリングします。Turboism は更新を確認し、署名検証済みのファーストパーティプラグインをバックグラウンドで自動更新します。一方でフレームワーク本体の更新は引き続き明示的な手順で行います。

## リリースチャンネル

| チャンネル | バージョンの形式 | 目的 |
| --- | --- | --- |
| `stable` | `X.Y.Z` | 日常利用。レビュー済みのリリースノートと翻訳。 |
| `beta` | `X.Y.Z-beta.N`、`X.Y.Z-rc.N`、または `X.Y.Z-alpha.N` | 安定化前の変更を事前にテストする。 |
| `nightly` | `X.Y.Z-0.nightly.BUILD` | ソース変更時のみ生成される日次開発ビルド。 |

- チャンネルが正当に `status: not_published` を返すことがあります。これはエラーではなく空のチャンネルを意味します。
- nightly ビルドは開発用ビルドです。利用前にプロジェクトをバックアップしてください。
- **0.67.0** 安定版以降、各リリースが提供する製品ダウンロードは `TurboismInstaller-<version>.exe` と `turboism-<version>.zip` の 2 つだけで、それぞれに対応する `.sha256` チェックサムが付きます。どちらにもすべての同梱ファーストパーティプラグインと完全なオフライン GraalJS エンジンが含まれます。開発者向け資産（`turboism-sdk-<version>.jar` と `turboism-event-processor-<version>.jar`）も併せて公開されます。
- 現在の安定版は **0.67.4** です。0.67.0 のベータ版（0.67.0-beta.3 〜 0.67.0-beta.7）は一時的に 4 つのダウンロードからなる Full/Thin 構成を使用していましたが、この構成は廃止されました。0.44.0 以前のリリースでは従来の資産（`TurboismInstaller-<version>.exe`、Java インストーラー `TurboismInstaller-<version>.jar`、`turboism-<version>-full.zip` / `turboism-<version>-lite.zip`）が使用されていました。Java インストーラーは現在公開されていません。

## 機械可読フィード

各チャンネルは JSON ドキュメントを公開します。

```text
https://api.turboism.dev/v1/releases/stable.json
https://api.turboism.dev/v1/releases/beta.json
https://api.turboism.dev/v1/releases/nightly.json
```

ドキュメントには、channel、選択された release（`version`、`tag`、`buildNumber`、`sourceRevision`、`publishedAt`）、ローカライズされた release notes、および asset ごとの name、size、SHA-256、checksum file、利用可能な source（`official` ミラーと `github`）の行が含まれます。条件付きリクエストに対応しています。サービスのエラー、空のレスポンス、失敗したリクエストを「最新である」と解釈してはいけません。

製品サイトも同じデータを [turboism.dev/download](https://turboism.dev/download) に使用しています。

## フレームワークを更新する

1. `config.json` と、重要な persistent プラグインの `config/`・`data/` の内容を backup します。
2. プラットフォームとチャンネルに合った新しいパッケージをダウンロードし、その SHA-256 チェックサムを検証します。
3. 新しいインストーラーを実行し、同じ Turboism home ディレクトリを対象にします。または、展開済みのポータブルアーカイブのファイルを置き換えます。
4. インストーラーにモード選択やプラグイン選択画面はありません。すべての同梱ファーストパーティプラグインを導入・更新し、廃止された公式プラグイン JAR を撤去し、既存の `disabledPlugins` を無効のまま保持します。廃止された 0.67.0 ベータ版の Thin インストーラーで導入した環境にも、同じ方法で同梱プラグインが導入されます。
5. 更新後に startup、plugin discovery、host capability status、logs を確認します。

インストーラーを再実行すると、同じ home が更新され、無関係な設定を盲目的に上書きすることはありません。更新の手段として Cubism installation file を上書きまたは書き換えないでください。

## プラグインの更新とバックグラウンド自動更新

### ファーストパーティプラグインの自動更新

0.67.0 以降、ファーストパーティプラグインはバックグラウンドで自動更新されます。

- ランタイムが署名付きカタログと照合してファーストパーティプラグインの更新を確認します。
- ダウンロードされた更新ファイルは、ステージング前に厳格な署名と整合性の検証を受けます。
- **ホットリロード**（hot-reload）対応プラグインは、Cubism を再起動することなく現在のセッションに即座に適用されます。
- その他のプラグイン更新は次回の Cubism 再起動時に適用されます。
- ユーザーはフレームワーク設定（**公式プラグインを自動的に更新する**、`settings.plugins.automatic-updates`）で公式プラグインの自動更新をいつでも無効化できます。
- 更新がインストールされるのは、その更新が宣言する Turboism API 範囲に実行中のフレームワークが含まれる場合のみです。一部の公式プラグインは API `0.67.2` または `0.67.4` を必要とします（[ファーストパーティプラグイン](./first-party-plugins)を参照）。これらを受け取るにはフレームワークを更新してください。
- **Turboism → プラグインマーケット…** または [turboism.dev/plugins](https://turboism.dev/plugins) から手動で更新・確認することも可能です。

### カスタムおよびサードパーティプラグイン

同じ plugin ID を持つ新しいプラグイン JAR を **Turboism → プラグイン管理… → JAR からインストール…** でインストールすると、Cubism の再起動後に適用される置換がステージングされます。

1. 現在の plugin JAR と重要な `config/<pluginId>/`・`data/<pluginId>/` をバックアップします。
2. プラグイン管理を通じて新しい JAR をインストールします。
3. Cubism を再起動します。
4. バージョン、状態、ログを確認します。

適用に失敗した場合、プライベートバックアップから以前のファイルが復元されます。

## 互換性に関する期待値

- Turboism は単一の public SDK 階層を公開します。source repository のレビュー済みバイナリ API ベースラインが compatibility gate です。
- API が存在しても、すべての Cubism version に Provider があるとは限りません。
- host-sensitive operation は、未サポートまたは未検証の version では利用できないままになることがあります。
- プラグインの API 範囲は、そのプラグインが必要とする最小の Turboism フレームワークバージョンから始まり、`1.0.0` の手前で終わります（例: `[0.67.0,1.0.0)`）。`[0.1.0,0.2.0)` を宣言する旧式のプラグインは拒否されます。
- plugin author は宣言された Turboism API range を使用し、unavailable behavior をテストすべきです。
- プラグイン管理には、各プラグインの API 範囲と宣言された正確な Cubism Editor バージョンが表示されます（0.67.2 以降）。
- 現在の安定版 0.67.4 は、5.0.00 から 5.3.04 までのレビュー済み全 20 の Cubism Editor バージョンに対応しており（[互換性](/docs/use/compatibility)を参照）、Windows x64 が対応するホストプラットフォームです。

## 更新チェッカー

Turboism は、デプロイ済みのリリース API（`api.turboism.dev/v1/releases/stable.json`）に対して stable 更新を確認します。比較にはインストール済みパッケージに埋め込まれた正規のビルド番号を使用するため、より低いビルドが更新として提示されることはなく、ビルド番号が同じでバージョンが異なる場合は更新ではなく識別情報の競合として扱われます。

利用可能な更新は、描画領域上のネイティブ Cubism ヒントとして提示されます。ヒントをクリックすると固定の公式ダウンロードページが開きます。インストーラーが自動でダウンロード・実行されることはありません。トップメニューの **Turboism → 更新を確認** から手動で随時確認することもできます。

更新チェックは UI をブロックせず、24 時間に最大 1 回だけ実行され、手動チェックは常に利用可能です。自動チェックは設定に専用の永続トグルがあり、Cubism 自身の更新抑制設定とは独立しています。

## 現在利用できないもの

- フレームワークインストーラーのバックグラウンド自動実行（フレームワーク更新にはインストーラーの実行または ZIP 展開が必要です）。
- 未検証のサードパーティ署名管理機関。
- 過去バージョンの無制限な履歴保存と復元 UI。
- Cubism 公式ランチャーのグローバルな変更。
