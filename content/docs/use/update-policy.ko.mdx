title: 업데이트 정책
description: Turboism과 플러그인을 안전하게 업데이트하고, 백그라운드 자동 업데이트를 이해하며 릴리스 채널을 선택합니다.
---

Turboism은 세 가지 채널에서 제품 버전을 게시하고 기계 판독 가능한 릴리스 피드를 통해 모든 패키지를 미러링합니다. Turboism은 업데이트를 확인하고 서명 검증된 퍼스트 파티 플러그인을 백그라운드에서 자동 업데이트하지만, 프레임워크 자체의 업데이트는 명시적인 수동 절차로 유지됩니다.

## 릴리스 채널

| 채널 | 버전 형식 | 목적 |
| --- | --- | --- |
| `stable` | `X.Y.Z` | 일상적인 사용. 검토된 릴리스 노트와 번역. |
| `beta` | `X.Y.Z-beta.N`, `X.Y.Z-rc.N` 또는 `X.Y.Z-alpha.N` | 변경 사항이 안정화되기 전에 미리 사용. |
| `nightly` | `X.Y.Z-0.nightly.BUILD` | 소스 변경 시에만 생성되는 일일 개발 빌드. |

- 채널이 정당하게 `status: not_published`를 보고할 수 있습니다. 이는 오류가 아니라 빈 채널을 나타냅니다.
- nightly 빌드는 개발 빌드입니다. 사용 전에 프로젝트를 백업하세요.
- **0.67.0-beta.3**부터 모든 채널은 정확히 4개의 패키지 자산(`TurboismInstaller-<version>-full.exe`, `TurboismInstaller-<version>-thin.exe`, `turboism-<version>-full.zip`, `turboism-<version>-thin.zip`)과 일치하는 `.sha256` 체크섬을 생성합니다. 0.67.0-beta.3 이전 릴리스에서는 기존 레거시 자산(`TurboismInstaller-<version>.exe`, Java 설치 프로그램 `TurboismInstaller-<version>.jar`, `turboism-<version>-lite.zip`)을 사용했습니다. Java 설치 프로그램 JAR은 폐지되었습니다.

## 기계 판독 가능한 피드

각 채널은 JSON 문서를 게시합니다:

```text
https://api.turboism.dev/v1/releases/stable.json
https://api.turboism.dev/v1/releases/beta.json
https://api.turboism.dev/v1/releases/nightly.json
```

문서에는 채널, 선택된 릴리스(`version`, `tag`, `buildNumber`, `sourceRevision`, `publishedAt`), 현지화된 릴리스 노트 및 이름, 크기, SHA-256, 체크섬 파일과 사용 가능한 소스(`official` 미러와 `github`)를 담은 에셋별 행이 포함됩니다. 조건부 요청이 지원됩니다. 서비스 오류, 빈 응답 또는 실패한 요청을 “최신 상태”로 취급해서는 안 됩니다.

제품 웹사이트는 [turboism.dev/download](https://turboism.dev/download)에 같은 데이터를 사용합니다.

## 프레임워크 업데이트

1. `config.json`과 중요한 영구 플러그인 `config/` 및 `data/` 내용을 백업하세요.
2. 사용 중인 플랫폼과 채널에 맞는 더 새로운 패키지를 다운로드하고 SHA-256 체크섬을 검증하세요.
3. 더 새로운 설치 프로그램을 실행하고 같은 Turboism home 디렉터리를 대상으로 지정하거나, 직접 압축을 푼 이식 가능한 아카이브의 파일을 교체하세요.
4. 변형 간 업그레이드는 안전합니다: 설치 프로그램에는 더 이상 모드나 플러그인 선택 페이지가 없습니다. Full 환경에 Thin을 덮어쓰면 기존 `plugins/` 디렉터리가 유지되며, Thin 환경에 Full을 덮어쓰면 기존 `disabledPlugins` 설정을 유지하면서 모든 기본 제공 퍼스트 파티 플러그인이 설치되거나 업데이트됩니다.
5. 업데이트 후 시작, 플러그인 검색, 호스트 기능 상태 및 로그를 확인하세요.

설치 프로그램을 다시 실행하면 관련 없는 구성을 무분별하게 덮어쓰지 않고 같은 home을 업데이트합니다. Cubism 설치 파일을 업데이트 수단으로 덮어쓰거나 재작성하지 마세요.

## 플러그인 업데이트 및 백그라운드 자동 업데이트

### 퍼스트 파티 플러그인 자동 업데이트

0.67.0-beta.3부터 퍼스트 파티 플러그인은 백그라운드에서 자동 업데이트됩니다:

- 런타임이 공식 카탈로그와 대조하여 퍼스트 파티 플러그인 업데이트를 확인합니다.
- 다운로드된 업데이트는 스테이징 전에 엄격한 디지털 서명 및 파일 무결성 검증을 거칩니다.
- **핫 리로드**(hot-reload)로 표시된 플러그인은 Cubism을 재시작하지 않고도 현재 세션에 즉시 적용됩니다.
- 기타 플러그인 업데이트는 다음 Cubism 재시작 시 적용됩니다.
- 사용자는 설정(`settings.plugins.automatic-updates`)에서 공식 플러그인 자동 업데이트를 언제든지 끌 수 있습니다.
- **Turboism → 플러그인 마켓…** 또는 [turboism.dev/plugins](https://turboism.dev/plugins)에서 수동으로 플러그인을 탐색하고 업데이트할 수도 있습니다.

### 커스텀 및 서드파티 플러그인

동일한 플러그인 ID의 새 플러그인 JAR을 **Turboism → 플러그인 관리… → JAR에서 설치…**를 통해 설치하면 Cubism 재시작 후 적용되는 교체 의도가 스테이징됩니다.

1. 현재 플러그인 JAR과 중요한 `config/<pluginId>/`, `data/<pluginId>/` 내용을 백업하세요.
2. 플러그인 관리를 통해 새 JAR을 설치하세요.
3. Cubism을 재시작하세요.
4. 버전, 상태 및 로그를 확인하세요.

적용이 실패하면 비공개 백업에서 이전 플러그인 파일이 복원됩니다.

## 호환성 기대 사항

- Turboism은 하나의 공개 SDK 등급을 제공합니다. 소스 저장소의 검토된 바이너리 API 기준선이 호환성 게이트입니다.
- API가 존재한다고 해서 모든 Cubism 버전에 프로바이더가 있다는 것이 보장되지는 않습니다.
- 호스트에 민감한 작업은 지원되지 않거나 검증되지 않은 버전에서 사용할 수 없을 수 있습니다.
- 플러그인 작성자는 선언된 Turboism API 범위를 사용하고 사용할 수 없는 동작을 테스트해야 합니다.
- 지원되는 Cubism Editor 버전은 Turboism 릴리스에 따라 다르며(Stable 0.44.0은 5.2.03, 5.3.02, 5.3.03, Beta 0.67.0-beta.1은 5.0.00–5.3.04. [호환성](/docs/use/compatibility) 참고), Windows x64가 지원되는 호스트 플랫폼입니다.

## 업데이트 검사기

Turboism은 배포된 릴리스 API(`api.turboism.dev/v1/releases/stable.json`)를 대상으로 안정 채널 업데이트를 확인합니다. 비교에는 설치된 패키지에 내장된 신뢰할 수 있는 빌드 번호를 사용하므로, 더 낮은 빌드가 업데이트로 제시되는 일은 없으며 빌드 번호가 같지만 버전이 다른 경우 업데이트가 아닌 식별 정보 충돌로 처리됩니다.

사용 가능한 업데이트는 그리기 영역 위의 네이티브 Cubism 힌트로 표시됩니다. 힌트를 클릭하면 고정된 자사 다운로드 페이지가 열리며 설치 프로그램이 자동으로 다운로드되거나 실행되지 않습니다. 상단 메뉴의 **Turboism → 업데이트 확인**을 통해 언제든지 수동으로 확인할 수도 있습니다.

업데이트 검사는 UI를 차단하지 않고 24시간에 최대 한 번만 실행되며, 수동 확인은 항상 사용할 수 있습니다. 자동 확인에는 설정에 전용 영구 토글이 있으며 Cubism 자체의 업데이트 억제 설정과 독립적입니다.

## 현재 사용할 수 없는 것

- 프레임워크 설치 프로그램의 백그라운드 자동 실행(프레임워크 업데이트는 설치 프로그램 실행 또는 ZIP 압축 해제 필요);
- 임의의 미검증 서드파티 서명 기관;
- 불변의 JAR 과거 세대 보관 및 롤백 UI;
- Cubism 공식 런처 파일의 전역 시스템 수정.
