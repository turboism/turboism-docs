title: 업데이트 정책
description: 설치 프로그램을 다시 실행해 Turboism을 업데이트하고 stable, beta 및 nightly 릴리스 채널 중에서 선택합니다.
---

Turboism은 세 채널로 제품 릴리스를 공개하고 모든 패키지를 기계 판독 가능한 릴리스 피드 뒤에 미러링합니다. Turboism은 안정 채널 업데이트를 자동으로 확인하지만, 업데이트 설치는 여전히 명시적인 수동 단계입니다. 설치 프로그램이 자동으로 다운로드되거나 실행되는 일은 없습니다.

## 릴리스 채널

| 채널 | 버전 형식 | 용도 |
| --- | --- | --- |
| `stable` | `X.Y.Z` | 일상적인 사용. 검토된 릴리스 노트와 번역. |
| `beta` | `X.Y.Z-beta.N`, `X.Y.Z-rc.N` 또는 `X.Y.Z-alpha.N` | 안정화되기 전의 예정된 변경을 사용해 봅니다. |
| `nightly` | `X.Y.Z-0.nightly.BUILD` | 소스가 변경된 경우에만 생성되는 일일 개발 빌드. |

- 채널은 정당하게 `status: not_published`를 보고할 수 있습니다. 이는 오류가 아니라 비어 있는 채널입니다.
- 나이틀리 빌드는 개발 빌드이므로 사용 전에 프로젝트를 백업하세요.
- 모든 채널은 동일한 네 가지 패키지 형식과 패키지별 SHA-256 체크섬 파일을 생성합니다.

## 기계 판독 가능한 피드

각 채널은 JSON 문서를 공개합니다:

```text
https://api.turboism.dev/v1/releases/stable.json
https://api.turboism.dev/v1/releases/beta.json
https://api.turboism.dev/v1/releases/nightly.json
```

문서에는 채널, 선택된 릴리스(`version`, `tag`, `buildNumber`, `sourceRevision`, `publishedAt`), 현지화된 릴리스 노트 및 이름, 크기, SHA-256, 체크섬 파일과 사용 가능한 소스(`official` 미러와 `github`)를 담은 에셋별 행이 포함됩니다. 조건부 요청이 지원됩니다. 서비스 오류, 빈 응답 또는 실패한 요청을 “최신 상태”로 취급해서는 안 됩니다.

제품 웹사이트는 [turboism.dev/download](https://turboism.dev/download)에 같은 데이터를 사용합니다.

## 프레임워크 업데이트

1. `config.json`과 중요한 영구 플러그인 `config/` 및 `data/` 내용을 백업하세요.
2. 사용 중인 플랫폼과 채널에 맞는 더 새로운 패키지를 다운로드하고 SHA-256 체크섬을 검증하세요.
3. 더 새로운 설치 프로그램을 실행하고 같은 Turboism home 디렉터리를 대상으로 지정하거나, 직접 압축을 푼 이식 가능한 아카이브의 파일을 교체하세요.
4. 업데이트의 일부로 플러그인 선택(Full, Thin 또는 Lite)을 다시 실행하세요.
5. 업데이트 후 시작, 플러그인 검색, 호스트 기능 상태 및 로그를 확인하세요.

설치 프로그램을 다시 실행하면 관련 없는 구성을 무분별하게 덮어쓰지 않고 같은 home과 선택을 업데이트합니다. Cubism 설치 파일을 업데이트 수단으로 덮어쓰거나 재작성하지 마세요.

## 플러그인 교체 또는 업데이트

같은 플러그인 ID로 더 새로운 플러그인 JAR을 설치하면 Cubism 재시작 후에 적용되는 교체 의도가 스테이징됩니다.

1. 현재 플러그인 JAR과 필요한 경우 플러그인의 영구 `config/<pluginId>/`, `data/<pluginId>/` 내용을 백업하세요.
2. 플러그인 관리를 통해 더 새로운 JAR을 설치하세요.
3. Cubism을 재시작하세요.
4. 표시되는 버전, 수명 주기 상태, 구성 마이그레이션 및 로그를 확인하세요.

적용이 실패하면 비공개 백업에서 이전 플러그인 파일을 복원합니다. 이 워크플로는 이전 세대를 보관하지 않으며 완전한 사용자 대상 복구, 롤백 또는 완전 제거 UI를 제공하지 않습니다.

## 호환성 기대 사항

- Turboism은 하나의 공개 SDK 등급을 제공합니다. 소스 저장소의 검토된 바이너리 API 기준선이 호환성 게이트입니다.
- API가 존재한다고 해서 모든 Cubism 버전에 프로바이더가 있다는 것이 보장되지는 않습니다.
- 호스트에 민감한 작업은 지원되지 않거나 검증되지 않은 버전에서 사용할 수 없을 수 있습니다.
- 플러그인 작성자는 선언된 Turboism API 범위를 사용하고 사용할 수 없는 동작을 테스트해야 합니다.
- 지원되는 Cubism Editor 버전은 5.2.03, 5.3.02, 5.3.03이며, Windows x64가 지원되는 호스트 플랫폼입니다.

## 업데이트 검사기

Turboism은 배포된 릴리스 API(`api.turboism.dev/v1/releases/stable.json`)를 대상으로 안정 채널 업데이트를 확인합니다. 비교에는 설치된 패키지에 내장된 신뢰할 수 있는 빌드 번호를 사용하므로, 더 낮은 빌드가 업데이트로 제시되는 일은 없으며 빌드 번호가 같지만 버전이 다른 경우 업데이트가 아닌 식별 정보 충돌로 처리됩니다. 빌드 번호 도입 이전의 설치는 계속 버전만으로 비교되며 임의로 만든 번호가 할당되지 않습니다.

사용 가능한 업데이트는 그리기 영역 위의 네이티브 Cubism 힌트로 표시됩니다. 힌트를 클릭하면 고정된 자사 다운로드 페이지가 열립니다. 릴리스 피드의 URL을 열거나 설치하지 않으며, 설치 프로그램을 자동으로 다운로드하거나 실행하지도 않습니다.

업데이트 검사는 UI를 차단하지 않고 24시간에 최대 한 번만 실행되며, 수동 확인은 항상 사용할 수 있습니다. 자동 확인에는 Startup 설정 탭에 전용 영구 토글이 있으며 Cubism 자체의 업데이트 억제 설정과 독립적입니다.

## 현재 사용할 수 없는 것

- 프레임워크 또는 플러그인 업데이트의 자동 다운로드 및 설치;
- 프로덕션 활성화된 마켓플레이스;
- 게시자 서명과 폐기;
- 보관된 변경 불가능한 JAR 세대;
- 완전한 사용자 대상 복구, 롤백 또는 되돌리기 UI;
- Cubism 런처의 전역 수정.

내장된 공식 디렉터리 클라이언트와 UI는 존재하지만 프로덕션 활성화는 준비되지 않았습니다. 프로덕션 키 목록이 비어 있고 실제 서명된 카탈로그 준비 상태가 확립되지 않았습니다.
