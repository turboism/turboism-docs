---
title: First-Party Plugins
description: The reviewed plugin bundle included in Full installations.
---

Full installations ship a reviewed bundle of first-party plugins. They use the same public SDK boundary as third-party plugins. Thin installations include zero plugins by default; plugins can be installed from the in-Cubism Plugin Market (**Turboism** menu → **Plugin Market…**) or from [turboism.dev/plugins](https://turboism.dev/plugins).

Availability of an individual feature still depends on the Cubism Editor version and the capability Providers that version exposes. A bundled plugin is not a promise that every feature works on every supported version; see [Compatibility](/docs/use/compatibility) for the per-plugin version ranges and feature deltas.

## Modeling

| Plugin | What it does |
| --- | --- |
| MaxRects-BSSF Layout Algorithm | Registers a MaxRects-BSSF texture-atlas packing algorithm with parallel search. |
| Mesh Edit Mirror Axis Enhance | Adds mirror-axis rotation and exact-host mirror-tool parity to mesh editing. |
| Parameter Batch Transfer | Batch-transfers the parameter bindings of one ArtMesh or Deformer to other parameters, with optional inversion. |
| Physics Editor | Adds Physics Settings group select-all and reopen retention. |

## Workflow

| Plugin | What it does |
| --- | --- |
| Cubism Tab Filter | Adds keyword filter boxes to the Parameter, Deformer, Scene, and Log palette tabs. |
| PSD Clip Mask Import | Imports ordered PSD clipping relationships into ArtMesh clip-mask assignments with an explicit overwrite policy. |
| History Panel | Projects the active document's native Undo history into a Photoshop-style pane with snapshot-bound Undo/Redo navigation. |
| Recent Preview | Captures bounded preview thumbnails for recent project files in the Recent Files hover popup. |
| WebDAV Auto-Backup Sync | Uploads Cubism auto-backup artifacts to a WebDAV endpoint using the JDK HTTP client. Plugin ID: `dev.turboism.plugin.webdav`. |
| Protected Export | Optional protected runtime-model export: works on a task-owned copy, flattens Warp/Rotation deformers, obfuscates ArtMesh identities, validates the complete staged output, and publishes atomically. Admitted only on reviewed Cubism versions and eligible models. |

## Integration and system

| Plugin | What it does |
| --- | --- |
| Turboism MCP Server | Loopback Model Context Protocol server exposing typed Cubism inspection, editing, history, and Editor-command workflows. Requires bearer authentication; see [MCP](../build-a-plugin/mcp). |

The built-in Turboism menu, settings, logs, About, plugin management, and update hints are not a plugin. They are provided by the runtime-owned framework shell (`dev.turboism.shell`) under the reserved `turboism.core` identity; plugin management lists it as a built-in, non-removable row that cannot be disabled or uninstalled. In Cubism Editor, the top menu is named **Turboism** (previously "插件"/Plugins) and includes items for: **Plugin Market…**, **Manage Plugins…**, **Plugin Settings…** (a dedicated two-pane window), **Check for Updates**, **Turboism Settings…**, **Keybindings…**, **Logs…**, plugin actions, and **About**.

## How to manage them

- Installers no longer have mode or plugin-selection pages: the Full installer installs every first-party plugin without per-plugin checkboxes, and the Thin installer installs zero plugins.
- On Thin (or to add more plugins), open **Turboism → Plugin Market…** or visit [turboism.dev/plugins](https://turboism.dev/plugins).
- Enable or disable an installed plugin from **Turboism → Manage Plugins…**; the change applies after Cubism restarts.
- Configure plugin preferences in the dedicated two-pane window via **Turboism → Plugin Settings…**.
- First-party plugins auto-update in the background after signature verification. Plugins marked hot-reload apply immediately, while others apply after restarting Cubism. Users can turn off automatic plugin updates in settings.
- Upgrades are safe across variants: running Thin over Full leaves existing plugins untouched; running Full over Thin installs or updates all first-party plugins while keeping existing disabled plugins disabled.
- [Plugin Management](./plugin-management) covers install, replacement, enable/disable, uninstall, and the data each plugin keeps.
- [Update Policy](./update-policy) covers how a newer bundle reaches an existing installation.
