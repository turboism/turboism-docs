---
title: Full and Thin Variants
description: Compare the Full and Thin download variants, understand safe upgrades, and view legacy package history.
---

Starting with **0.67.0-beta.3**, Turboism ships exactly four product downloads across two variants instead of wizard-based installer modes:

- **Full** (`TurboismInstaller-<version>-full.exe`, `turboism-<version>-full.zip`) — runtime framework plus every bundled first-party plugin.
- **Thin** (`TurboismInstaller-<version>-thin.exe`, `turboism-<version>-thin.zip`) — runtime framework only, with zero first-party plugins.

In Thin installations, plugins are installed later from the in-Cubism Plugin Market (**Turboism** menu → **Plugin Market…**) or from [turboism.dev/plugins](https://turboism.dev/plugins).

Neither variant alters Cubism installation files or licensing state.

## Full vs Thin boundary

| Capability | Full variant | Thin variant |
| --- | --- | --- |
| Runtime framework & Java agent | Included | Included |
| Configurator (`configure_turboism.ps1`) | Included | Included |
| Bundled first-party plugins | All included in `plugins/` | None included |
| Plugin acquisition | Pre-installed | From in-Cubism Plugin Market or web directory |
| Plugin management & toggles | **Turboism → Manage Plugins…** | **Turboism → Manage Plugins…** |
| Background auto-updates | Verified first-party plugin updates | Verified first-party plugin updates |

### No mode or plugin-selection wizard pages

The installers no longer have mode selection or per-plugin selection pages:

- `TurboismInstaller-<version>-full.exe` installs all first-party plugins without individual checkboxes.
- `TurboismInstaller-<version>-thin.exe` installs only the framework files.
- Plugins can be enabled or disabled later inside Cubism via **Turboism → Manage Plugins…**; changes apply after restarting Cubism.
- Verified first-party plugins auto-update in the background. Plugins marked hot-reload apply immediately, while other updates apply after restarting Cubism. Users can turn off automatic plugin updates in settings.

## Safe upgrades between variants

Running installers across variants is safe and idempotent:

- **Thin over Full**: running the Thin installer over an existing Full installation updates the framework while leaving your existing `plugins/` directory untouched.
- **Full over Thin**: running the Full installer over an existing Thin installation installs or updates all bundled first-party plugins while respecting existing `disabledPlugins` entries in `config.json`.

In both cases, user settings in `config.json` and Cubism installation links in `cubism-installations.json` are preserved.

## Optional engine and GraalVM components

The Windows installer offers an optional component to acquire the JavaScript engine and GraalVM dependencies:

- Leaving it unselected keeps the framework and Java plugins complete and fully operational.
- You can install or download the engine later via `install-script-engine.ps1` or settings.
- The development-only `Turboism with fx` plugin and managed fx runtime bytes are never included in release packages.

## Legacy packages (releases before 0.67.0-beta.3)

Releases before **0.67.0-beta.3** used a legacy packaging model:

- A single Windows installer `TurboismInstaller-<version>.exe` that featured wizard pages for selecting between Full and Lite modes, as well as per-plugin component checkboxes.
- A cross-platform IzPack Java installer `TurboismInstaller-<version>.jar` (requiring Java 17 or newer) that offered Full, Thin, and Lite modes.
- Portable archives distributed as `turboism-<version>-full.zip` and `turboism-<version>-lite.zip`.

Starting with 0.67.0-beta.3:
- The Java installer JAR is retired. macOS and Linux use the portable ZIP packages.
- The "Lite" tier is replaced by the standalone Thin variant (`-thin.exe` and `-thin.zip`).
- Per-plugin installer selection is superseded by the in-Cubism Plugin Market and Manage Plugins windows.
