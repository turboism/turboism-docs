---
title: 更新策略
description: 安全更新 Turboism 及插件，了解后台自动更新，并在各发布渠道之间做出选择。
---

Turboism 在三个渠道发布产品版本，并在机器可读的发布信息源后镜像每个安装包。Turboism 会自动检查更新并在后台自动更新经签名验证的第一方插件，而框架更新仍需明确的手动步骤。

## 发布渠道

| 渠道 | 版本形态 | 用途 |
| --- | --- | --- |
| `stable` | `X.Y.Z` | 日常使用。已审查的发行说明和翻译。 |
| `beta` | `X.Y.Z-beta.N`、`X.Y.Z-rc.N` 或 `X.Y.Z-alpha.N` | 在变更稳定之前提前试用。 |
| `nightly` | `X.Y.Z-0.nightly.BUILD` | 每日开发构建，仅在源代码发生变化时产出。 |

- 渠道可以合法地报告 `status: not_published`；这表示渠道为空，而不是错误。
- nightly 构建是开发构建：使用前请备份项目。
- 自 **0.67.0-beta.3** 起，每个渠道严格产出四种产品构件：`TurboismInstaller-<version>-full.exe`、`TurboismInstaller-<version>-thin.exe`、`turboism-<version>-full.zip` 和 `turboism-<version>-thin.zip`，并附带配对的 `.sha256` 校验和。0.67.0-beta.3 之前的历史版本采用旧版构件（`TurboismInstaller-<version>.exe`、Java 安装器 `TurboismInstaller-<version>.jar` 以及 `turboism-<version>-lite.zip`）。Java 安装器 JAR 已退役。

## 机器可读的信息源

每个渠道发布一份 JSON 文档：

```text
https://api.turboism.dev/v1/releases/stable.json
https://api.turboism.dev/v1/releases/beta.json
https://api.turboism.dev/v1/releases/nightly.json
```

文档包含渠道、所选发行版（`version`、`tag`、`buildNumber`、`sourceRevision`、`publishedAt`）、本地化发行说明，以及每个资产的一行记录，含名称、大小、SHA-256、校验和文件和可用来源（`official` 镜像与 `github`）。支持条件请求。服务错误、空响应或请求失败都不得被视为“已是最新”。

产品网站使用相同的数据支撑 [turboism.dev/download](https://turboism.dev/download)。

## 更新框架

1. 备份 `config.json` 以及任何重要的持久化插件 `config/` 和 `data/` 内容。
2. 下载适用于你的平台和渠道的更新安装包，并验证其 SHA-256 校验和。
3. 运行新版安装器并指向同一个 Turboism home 目录，或替换你解压出的便携归档中的文件。
4. 变体间升级安全可靠：安装器不再包含模式或插件选择页。使用 Thin 覆盖 Full 安装时原样保留现有的 `plugins/` 目录；使用 Full 覆盖 Thin 安装时安装或更新全部随包第一方插件，并保留现有的 `disabledPlugins` 停用设置。
5. 更新后验证启动、插件发现、宿主 capability 状态和日志。

重新运行安装器会更新同一个 home，不会盲目覆盖无关配置。不要把覆盖或重写 Cubism 安装文件作为更新机制。

## 插件更新与后台自动更新

### 第一方插件自动更新

自 0.67.0-beta.3 起，第一方插件可在后台自动更新：

- 运行时会对照官方在线目录检查第一方插件更新。
- 下载的更新在暂存前经过严格的数字签名与文件完整性校验。
- 标记为**热更新**（hot-reload）的插件会在当前会话中即刻生效，无需重启 Cubism。
- 其他插件更新会在下一次重启 Cubism 时应用。
- 用户可在设置中随时关闭官方插件自动更新（`settings.plugins.automatic-updates`）。
- 你也可以随时通过 **Turboism → 插件市场…** 或访问 [turboism.dev/plugins](https://turboism.dev/plugins) 手动浏览和更新插件。

### 本地与第三方插件

通过 **Turboism → 管理插件… → 从 JAR 安装…** 安装具有相同 plugin ID 的新版插件 JAR 会提交替换意图，并在 Cubism 重启后生效。

1. 在重要时备份当前插件 JAR 以及插件的持久化 `config/<pluginId>/` 和 `data/<pluginId>/` 内容。
2. 通过插件管理安装新版 JAR。
3. 重启 Cubism。
4. 验证显示的版本、生命周期状态、配置迁移和日志。

应用失败时，会从私有备份恢复之前的插件文件。

## 兼容性预期

- Turboism 发布单一的公共 SDK 层级。源代码仓库中已审查的二进制 API 基线是兼容性门禁。
- API 存在并不保证每个 Cubism 版本都有 Provider。
- 不受支持或未经验证的版本上的宿主敏感操作可能仍然不可用。
- 插件作者应使用已声明的 Turboism API 范围，并测试不可用行为。
- 受支持的 Cubism Editor 版本取决于 Turboism 发行版（Stable 0.44.0 为 5.2.03、5.3.02 和 5.3.03；Beta 0.67.0-beta.2 为 5.0.00–5.3.04；请参阅[兼容性](/docs/use/compatibility)），Windows x64 是受支持的宿主平台。

## 更新检查

Turboism 会针对已部署的发布 API（`api.turboism.dev/v1/releases/stable.json`）检查稳定版更新。比较使用安装包内嵌的权威构建号，因此更低的构建号永远不会被当作更新提供，构建号相同但版本不同的情况会被视为身份冲突而不是更新。

可用更新以绘图区上的原生 Cubism 提示呈现。点击提示会打开固定的官方下载页；不会自动下载或执行安装程序。你也可以通过顶部菜单中的 **Turboism → 检查更新** 随时进行手动检查。

更新检查不阻塞界面，最多每 24 小时运行一次，并始终提供手动检查。自动检查在设置中有独立的持久开关，且不受 Cubism 自身更新抑制设置的影响。

## 当前不可用

- 框架安装程序的自动静默下载与后台执行（框架更新需手动运行安装器或解压 ZIP）；
- 未经验证的第三方签名权威机构；
- 保留不可变的 JAR 历史版本回滚 UI；
- 对 Cubism 官方启动文件的全局系统级修改。
