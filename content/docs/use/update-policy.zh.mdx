---
title: 更新策略
description: 替换插件并通过重新运行安装器更新框架，同时了解目前尚不存在的自动更新能力。
---

Turboism 当前支持本地 JAR 替换和手动重新运行安装器，而不是生产级自动更新系统。

## 当前的插件替换

安装具有相同 plugin ID 的新版插件 JAR 会分阶段提交替换意图，并在 Cubism 重启后生效。

1. 备份当前插件 JAR。
2. 在重要时备份持久化的 `config/<pluginId>/` 和 `data/<pluginId>/` 内容。
3. 通过插件管理安装新版 JAR。
4. 重启 Cubism。
5. 验证版本、生命周期状态、配置迁移和日志。

应用失败时，会从私有 backup 恢复之前的插件文件。此工作流不会保留历史 generation，也不提供完整的用户面向修复、回滚或清理 UI。

## 框架安装器更新

新版框架通过重新运行安装包安装：

1. 从提供构建的 release 或 preview 渠道获取更新的 `TurboismInstaller-<version>.exe`（Windows）或 `TurboismInstaller-<version>.jar`（Windows/macOS）。
2. 备份 `config.json` 以及任何重要的持久化插件 `config/` 和 `data/` 内容。
3. 运行新版安装器，并指向同一个 Turboism home 目录。
4. 在更新过程中重新运行插件选择（Lite/Full）。
5. 更新后验证启动、插件发现、宿主 capability 状态和日志。

重新运行安装器会更新同一个 home 和选择，不会盲目覆盖无关配置。目前还没有自动在线更新器，也没有签名的公开下载渠道；安装器更新是手动重新运行。不要把覆盖或重写 Cubism 安装文件作为更新机制。

## 兼容性预期

- 新 SDK API 默认是 Preview。
- API 存在并不保证每个 Cubism 版本都有 Provider。
- 不受支持或未经验证的版本上的宿主敏感操作可能仍然不可用。
- 插件作者应使用已声明的 Turboism API 范围，并测试不可用行为。
- 生成的 API 参考跟踪当前开发源代码，而不是最终 Stable 发布线。

## 当前不可用

- 生产级在线更新发现和下载；
- marketplace 渠道；
- 发布者签名和撤销；
- 保留不可变的 JAR generation；
- 完整的用户面向修复、回滚或恢复 UI；
- 自动系统级安装器更新；
- 已发布的 Stable 兼容性矩阵。

内置的 Official Directory 客户端和 UI 已存在，但生产激活尚未就绪：签名端点和密钥就绪性尚不完整。
