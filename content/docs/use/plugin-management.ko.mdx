---
title: 플러그인 관리
description: 로컬 Turboism 플러그인 JAR을 안전하게 설치, 교체, 사용, 사용 안 함 및 제거합니다.
---

Turboism은 로컬 플러그인 JAR을 설치하는 두 가지 방법을 제공합니다: 관리형 설치(권장)와 수동 설치(고급/대체). 이것은 시스템 수준의 Turboism 설치 프로그램이 아닙니다. Full 설치에는 이미 검토된 [기본 제공 플러그인 번들](./first-party-plugins)이 포함되어 있으며, 서드파티 플러그인도 같은 관리형 흐름으로 추가할 수 있습니다.

모든 플러그인 관리 변경은 스테이징되며 Cubism 재시작 후에 적용됩니다. 현재 로드된 플러그인 인스턴스를 핫 스왑하지 않습니다.

## 관리형 설치(권장)

1. 신뢰하는 소스에서 플러그인 JAR을 빌드하거나 획득하세요.
2. Turboism 플러그인 관리를 여세요.
3. **JAR에서 설치…**(Install from JAR…)를 선택하세요.
4. 로컬 `.jar` 파일을 선택하세요.
5. JAR을 로컬/검증되지 않은 소스로 표시하는 대화 상자를 확인하세요.
6. 작업이 대기 중으로 표시되는지 확인하세요.
7. Cubism을 정상적으로 종료하세요.
8. 같은 Turboism home으로 Cubism을 다시 시작하세요.
9. 플러그인 목록과 런타임 로그에서 실제 적용된 상태를 확인하세요.

스테이징 전에 런타임은 선택한 JAR을 신뢰할 수 없는 로컬 입력으로 취급합니다. 제한된 아카이브 한도(원시 크기, 항목별 크기, 총 확장 크기, 항목 수 및 압축률) 안에서 심볼릭 링크가 아닌 일반 JAR을 열고, 디스크립터 하나와 플러그인 콘텐츠를 정확히 검사한 다음, 페이로드를 대기 상태로 스냅샷합니다.

스테이징 저널은 원시 JAR의 SHA-256과 크기, 디스크립터 해시, 플러그인 ID 및 버전을 기록합니다. 다음 시작 시 런타임은 적용 전에 스테이징된 JAR을 그 신원과 다시 검증합니다.

## 플러그인 교체 또는 업데이트

현재 별도의 프로덕션 업데이트 서비스는 없습니다. 같은 플러그인 ID로 더 새로운 JAR을 설치하면 교체 의도가 스테이징됩니다.

권장 절차:

1. 현재 JAR과 플러그인의 영구 구성/데이터를 백업하세요.
2. 플러그인 관리를 통해 더 새로운 JAR을 설치하세요.
3. Cubism을 재시작하세요.
4. 표시되는 버전, 수명 주기 상태, 구성 마이그레이션 및 로그를 확인하세요.

시작 사전 검사는 스테이징된 JAR을 다시 검증하고, 적용이 실패하면 비공개 백업에서 이전 플러그인 파일을 복원합니다. 보관된 이전 버전 목록은 없으며, 완전한 사용자 대상 복구, 롤백, 되돌리기 또는 완전 제거 UI도 없습니다.

## 플러그인 사용 안 함 또는 사용

원하는 상태는 Turboism home 구성에 저장되며 재시작 후에 적용됩니다.

- 런타임이 소유한 `turboism.core` 플러그인은 비활성화할 수 없습니다;
- 비활성화된 플러그인은 다음 시작 시 검색에서 제외됩니다;
- 토글을 변경해도 활성 인스턴스가 즉시 언로드되지 않습니다;
- 정상 종료 시에도 플러그인은 스코프와 ClassLoader 참조를 닫을 기회를 얻습니다.

## 플러그인 제거

1. 플러그인 관리에서 플러그인을 선택하세요.
2. **제거**를 선택하세요.
3. 대기 중인 작업을 확인하세요.
4. Cubism을 종료하고 재시작하세요.
5. 플러그인이 더 이상 로드되지 않는지 확인하세요.
6. 데이터를 유지할지 삭제할지 결정하세요.

코어 플러그인은 제거할 수 없습니다.

플러그인 JAR을 삭제해도 플러그인이 소유한 모든 파일이 자동으로 지워지지는 않습니다:

- 재설치 후 설정이나 비즈니스 데이터가 필요할 수 있으면 `config/<pluginId>/`와 `data/<pluginId>/`를 유지하세요;
- `cache/<pluginId>/`, `state/<pluginId>/`, `logs/<pluginId>/`는 일반적으로 다시 만들 수 있거나 진단용이지만, Turboism이 중지된 상태에서만 삭제하세요;
- 구성이나 영구 데이터를 삭제하면 백업 없이는 되돌릴 수 없습니다.

## 수동 설치

수동 설치는 신뢰하는 플러그인 JAR을 위한 고급/대체 경로입니다. 관리형 스테이징을 거치지 않고 플러그인 JAR을 Turboism home의 `plugins/` 디렉터리에 직접 복사합니다. 일반 사용자는 위의 관리형 설치를 우선 사용해야 합니다.

수동 복사는 아래 비교에 설명된 관리형 안전 장치를 우회합니다. 런타임은 여전히 시작 검증을 수행하지만, 시작 검증은 관리형 사전 검사와 동등하지 않습니다.

플러그인 JAR은 플러그인 소스에서 빌드한 JAR입니다. Turboism 설치 프로그램 파일인 `TurboismInstaller-<version>.jar`이 아닙니다.

### 플러그인 JAR 수동 설치

1. Cubism과 Turboism을 완전히 종료하세요. 플러그인 JAR은 시작 시 검사되므로, 변경 사항은 완전히 중지하고 재시작한 뒤에만 적용됩니다.
2. 런처가 사용하는 정확한 Turboism home을 확인하세요.
3. `<turboism.home>/plugins/`를 만들거나 여세요.
4. 플러그인 JAR을 `<turboism.home>/plugins/`의 루트에 직접 복사하고, 플러그인 ID마다 JAR을 최대 하나만 유지하세요. 중첩된 폴더에 두거나 심볼릭 링크를 사용하지 마세요.
5. 같은 Turboism home으로 Cubism을 다시 시작하세요.
6. 플러그인 목록/상태와 런타임 로그를 확인하세요.

`plugins/` 위치는 런처와 설치 모드에 따라 다릅니다:

- Windows `.exe` 설치 프로그램 기본값: `%LOCALAPPDATA%\Turboism\plugins\`
- 사용자 지정 `.exe`/`.jar` 설치 프로그램 home: `<선택한 Turboism 디렉터리>/plugins/`

### 수동 설치한 플러그인 교체 또는 업데이트

1. 먼저 Cubism과 Turboism을 중지하세요.
2. 이전 JAR과 플러그인의 중요한 `config/<pluginId>/`, `data/<pluginId>/` 내용을 백업하세요.
3. 교체본을 복사하기 전에 같은 ID의 이전 JAR을 제거하세요. 같은 플러그인 ID를 가진 JAR 두 개는 `DUPLICATE_PLUGIN_ID`로 실패합니다.
4. 같은 Turboism home으로 재시작하고 버전, 상태 및 로그를 확인하세요.

### 수동 설치한 플러그인 제거

1. Cubism과 Turboism을 중지하세요.
2. `<turboism.home>/plugins/`에서 플러그인 JAR을 제거하세요.
3. 재시작하고 플러그인이 더 이상 로드되지 않는지 확인하세요.
4. 의도적으로 삭제하지 않는 한 플러그인 데이터는 남습니다. Turboism이 중지된 상태에서 백업이 있을 때만 `config/<pluginId>/` 또는 `data/<pluginId>/`를 삭제하세요.

### 관리형 설치와 수동 설치 비교

관리형 설치는 다음을 추가로 제공합니다:

- UI 확인과 대기 중 작업 추적;
- 소스 경로 확인과 제한된 아카이브 한도 안에서의 엄격한 아카이브 사전 검사;
- 비공개 스냅샷, 대기 저널 및 스테이징된 적용;
- 스테이징된 적용이 실패할 때 관리형 백업/복원.

수동 설치는 위의 모든 항목을 우회하지만, 복사한 JAR은 여전히 시작 검증을 거칩니다: 디스크립터 파싱/스키마, 플러그인 JAR 콘텐츠 계약, 예약 ID, Turboism API 범위, 종속성, 비활성화된 ID, 진입점 로딩 및 수명 주기.

## JAR 거부

관리형 JAR은 다음과 같은 이유로 거부될 수 있습니다:

- 심볼릭 링크이거나 일반 파일이 아닌 소스 경로;
- 크기, 항목, 확장 또는 압축률 한도 위반;
- 잘못되었거나 모호한 ZIP 경로;
- 중복 항목 또는 특수 파일;
- `META-INF/turboism/plugin.json`이 하나가 아니거나 중복됨;
- 디스크립터 ID, 버전 또는 API 범위 불일치;
- 복사된 SDK, 런타임, 테스트 또는 Live2D 클래스;
- 네이티브 또는 설치 프로그램 페이로드;
- 중첩 JAR 콘텐츠;
- 누락된 진입점 클래스, 선언된 리소스 또는 i18n 카탈로그.

현재 플러그인 소스에서 JAR을 다시 빌드하세요. 아카이브를 수동으로 편집하거나 검사를 비활성화하지 마세요. 위 사유는 관리형 사전 검사를 설명합니다. 수동 복사는 이를 건너뛰며, 시작 검증이 강제하는 위반만 런타임 시작 진단에 나타납니다.

## 현재 제한 사항

플러그인 관리는 현재 다음을 제공하지 않습니다:

- 서드파티 플러그인 검색 또는 다운로드;
- 게시자 서명 또는 폐기;
- 라이브 마켓플레이스;
- 보관된 이전 버전;
- 완전한 사용자 대상 복구, 롤백, 되돌리기 또는 완전 제거 UI;
- Cubism 설치 또는 런처의 시스템 수준 수정.

내장된 공식 디렉터리 클라이언트와 UI는 존재하지만 프로덕션 활성화는 준비되지 않았습니다. 프로덕션 키 목록이 비어 있고 실제 서명된 카탈로그 준비 상태가 확립되지 않았습니다.
