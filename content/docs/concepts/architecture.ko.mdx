---
title: 아키텍처
description: Turboism이 플러그인과 Live2D Cubism Editor 사이에 위치하는 방식입니다.
---

Turboism은 Live2D Cubism Editor 내부와 확장 코드 사이의 적응 계층입니다. 호스트 구현 세부 사항에 직접 의존하지 않고도 플러그인 작성자에게 안정적인 통합 표면을 제공합니다.

## 의존 방향

```text
Plugin -> SDK -> Runtime policy -> versioned Adapter/Provider -> Cubism/Editor
```

- **플러그인**은 사용자 워크플로를 설명하며 SDK에만 의존합니다.
- **SDK**는 Turboism이 소유한 타입, 서비스 및 수명 주기 계약을 노출합니다.
- **런타임**은 호스트 접근, 수명 주기, 권한, 스레딩, 트랜잭션, 진단, 호환성 및 버전 라우팅을 담당합니다.
- **어댑터/프로바이더** 계층은 정확한 Cubism Editor 버전별로 호스트 고유 심볼을 격리합니다.
- **Cubism/Editor**는 별도로 설치하고 라이선스를 취득하는 호스트 애플리케이션으로 남습니다.

## 여기서 따르는 설계 규칙

- 하나의 공개 SDK 등급. 플러그인은 `com.live2d.*` 타입, 호스트 위젯, 네이티브 핸들, 호스트 ClassLoader 또는 런타임 구현 타입을 절대 보지 않습니다.
- 실행은 런타임이 소유합니다. 플러그인은 관리되지 않는 스레드, 실행기 또는 타이머를 만들지 않고 바이트코드 트랜스포머를 등록하지 않습니다.
- 쓰기는 검증, Undo, 변경 상태 처리 및 오래된 참조 거부를 갖춘 Editor 소유 작업입니다.
- 기능은 안전하게 실패합니다. 사용할 수 없는 프로바이더, 검증되지 않은 호스트 버전 또는 오래된 오브젝트 참조는 대체 경로 대신 타입이 지정된 실패를 발생시킵니다.
- 검증은 집중 테스트부터 패키징된 통합, 릴리스 게이트 및 명시적인 정확한 버전 호스트 검증까지 비용과 위험에 따라 계층화됩니다.
