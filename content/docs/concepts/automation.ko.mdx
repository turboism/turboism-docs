---
title: 자동화
description: Turboism이 지원하는 확장 경로와 이들이 공유하는 안전 경계입니다.
---

Turboism은 세 가지 확장 경로와 그 위에 기본 제공 플러그인이 구축하는 자동화를 지원합니다.

## 1. Java 플러그인

SDK 수명 주기, 플러그인 디스크립터, 선언된 권한 및 `PluginContext` 서비스를 갖춘 프로세스 내 Java 17 JAR입니다. 완전한 확장 경로이며 에디터 자체의 상태에 참여하는 모든 것에 사용해야 하는 방식입니다.

## 2. GraalJS 스크립트

Java 플러그인이 `PluginContext.scripts()`를 통해 검색하고 `ScriptService.run`으로 명시적으로 실행하는 제한된 JavaScript입니다. 검색은 스크립트를 절대 실행하지 않으며, 스크립트는 완전한 Java SDK가 아니라 제한된 브리지를 받습니다. [GraalJS 스크립트](../build-a-plugin/graaljs-scripts)를 참고하세요.

## 3. MCP

번들로 제공되는 Turboism MCP Server 플러그인은 신뢰하는 로컬 외부 클라이언트를 위해 인증된 루프백 Streamable HTTP 엔드포인트를 노출합니다. 직접 실행하는 도구를 위한 통합 경로이며 프로세스 내 API가 아닙니다. [MCP](../build-a-plugin/mcp)를 참고하세요.

ACP는 Turboism with fx의 내부용이며 네 번째 확장 경로가 아닙니다.

## 이 경로들 위에 구축된 자동화

기본 제공 플러그인은 이미 여러 워크플로를 자동화합니다. 예를 들어 Cubism 자동 백업 아티팩트를 WebDAV 엔드포인트에 업로드하고, 순서가 있는 PSD 클리핑 관계를 ArtMesh 클립 마스크로 가져오며, MCP를 통해 타입이 지정된 Cubism 검사, 편집 및 히스토리 작업을 노출합니다.

## 안전 경계

자동화는 프로젝트 콘텐츠를 변경할 수 있으므로 경로와 관계없이 하나의 경계를 공유합니다:

- 사용자 행동이나 명시적인 사용자 권한이 작업을 시작해야 합니다;
- 파일을 쓰거나, 백업을 만들거나, 네트워크 서비스에 연결하는 작업은 눈에 보이고 권한으로 제어된 상태로 유지됩니다;
- 쓰기 작업은 해당 작업이 주장하는 경우 Undo와 변경 상태 처리를 갖춘 Editor 소유 트랜잭션을 거칩니다;
- 플러그인은 바이트코드 트랜스포머를 등록할 수 없고, 스크립트는 호출자가 제공한 브리지 이상에 도달할 수 없습니다;
- 지원되지 않거나 검증되지 않은 기능은 안전하게 실패합니다.

콘텐츠를 변경하는 자동화를 활성화하기 전에 중요한 프로젝트의 독립적인 백업을 보관하세요. [안전 및 권리](../safety-and-rights)와 [개발 상태](../development-status)를 참고하세요.
