호스트 애플리케이션은 버전 간에 심볼과 구현 세부 사항을 변경합니다. 매핑 계층은 그 호스트 고유 지식이 플러그인 경험과 격리된 상태로 유지되는 경계입니다.

## 존재하는 이유

Cubism Editor 내부는 공개 API가 아닙니다. 클래스 이름, 메서드 시그니처, 필드 레이아웃 및 평가 동작은 버전마다 다르며, 한 빌드에 존재하는 심볼이 다른 빌드에서는 없거나 이름이 바뀌었거나 다르게 동작할 수 있습니다.

명시적인 경계가 없으면 모든 플러그인이 리플렉션, 버전 확인 및 호스트 오브젝트 가정으로 그 문제를 스스로 해결해야 합니다. 그러면 플러그인 코드는 호스트와 똑같은 방식으로 취약해지고, Turboism은 지원되지 않는 조합에 대해 안전하게 실패할 수 없게 됩니다.

## Turboism이 격리하는 방식

- 플러그인은 공개된 SDK 타입을 대상으로 하며 `com.live2d.*` 클래스를 절대 로드하지 않습니다.
- 런타임은 감지된 호스트 빌드에 대해 정확한 버전의 어댑터와 프로바이더를 선택합니다.
- Cubism Editor 5.2.03, 5.3.02, 5.3.03은 허용된 정확한 버전이며, 목록에 없는 버전은 조용히 호환되는 것으로 취급되지 않습니다.
- 호스트 멤버 선택은 검토된 근거로 기록되고 고정되므로, 고정된 신원과 일치하지 않는 빌드는 추측 대신 실패합니다.
- 공개 Cubism 값은 플러그인 코드에 도달하기 전에 변경 불가능한 Turboism 소유 타입으로 복사됩니다.
- 모델 오브젝트와 참조는 세대에 바인딩되며, 프로젝트 닫기, 문서 전환, 모델 다시 로드, 오브젝트 삭제, 플러그인 사용 안 함, 프로바이더 교체 또는 지원되지 않는 버전 전환 후에는 유효하지 않게 됩니다.

## 플러그인 작성자에게 이는 무엇을 의미하는가

사용 불가 상황은 여전히 처리해야 하지만, 예측 가능한 한 곳에서 처리합니다. 즉 타입이 지정된 "지원되지 않음" 또는 "사용할 수 없음" 결과입니다. 자체 리플렉션 계층이 필요하지 않으며 작성해서도 안 됩니다. 호스트에 직접 접근하는 플러그인은 매핑, 권한 모델 및 실패를 이해 가능하게 만드는 진단을 우회합니다.

오브젝트 API와 기능 모델은 [SDK API 가이드](../reference/sdk-api)를, 현재 허용된 버전은 [개발 상태](../development-status)를 참고하세요.
