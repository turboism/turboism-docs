---
title: Troubleshooting and Feedback
description: Diagnose Preview startup, plugin package, lifecycle, permission, and Provider failures.
---

## Turboism does not start

- Confirm you are using the intended Preview directory and Turboism home.
- Check the Java Agent and Runtime logs in Preview-owned or home-owned log directories.
- Verify that the active Cubism artifact matches the supported Preview envelope.
- Do not replace Cubism JARs, DLLs, BAT files, or licensing components to bypass an identity failure.

## A plugin does not appear

Check that:

- the loose JAR is under a configured relative `pluginDirs` entry, or the `.tplugin` installation completed after restart;
- the JAR has exactly one `META-INF/turboism/plugin.json`;
- the manifest uses schema version 2;
- the entrypoint class exists, is public, implements `TurboismPlugin`, and has a public no-argument constructor;
- the Turboism API range and required dependencies resolve;
- the plugin ID is not disabled or duplicated;
- `environment.requiresCubism` matches the current environment.

## A package is rejected

A `.tplugin` can be rejected for invalid hashes, malformed paths, duplicate entries, special files, copied SDK/Runtime/Live2D classes, native or installer payloads, nested JARs outside the accepted profile, descriptor mismatches, missing entrypoints, or undeclared resources.

Regenerate the package from the current plugin JAR. Do not edit the archive manually or disable package inspection.

## An operation remains pending

Plugin install, replacement, enable, disable, and uninstall operations apply after Cubism restarts.

- Confirm Cubism exited fully and was restarted.
- Confirm the same `turboism.home` is used on both launches.
- Inspect Runtime state and logs.
- Do not edit plugin, config, and pending-state files while Turboism is running.

## A host capability is unavailable

This is often a deliberate fail-closed result caused by host version, artifact identity, mapping verification, Provider availability, safe mode, or stale object generation.

Record the exact Cubism version, artifact identity, operation, and diagnostic code. Do not bypass the failure with reflection or direct host access.

## Feedback

Documentation corrections and non-sensitive product discussion belong in the public documentation repository:

- https://github.com/turboism/turboism-docs

Feature/runtime defects should include the relevant Turboism source revision, Cubism version, sanitized logs, and reproduction steps. Do not attach proprietary Cubism binaries, private resources, licensing material, or user projects.
