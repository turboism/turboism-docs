Turboism SDK는 플러그인의 유일한 공개 종속성입니다. Turboism은 하나의 공개 SDK 등급을 제공하며, 소스 저장소의 검토된 바이너리 API 기준선이 호환성 게이트입니다. 가용성은 네 가지 별개의 사실에 따라 달라집니다:

1. API가 SDK에 존재합니다;
2. 플러그인이 필요한 권한을 선언합니다;
3. 런타임에 일치하는 기능 프로바이더가 있습니다;
4. 활성 Cubism 버전과 오브젝트 세대가 지원됩니다.

생성된 타입 및 메서드 인덱스는 [SDK HTML API 레퍼런스](https://turboism.dev/sdk/index.html)를 여세요.

## 플러그인 수명 주기

모든 진입점은 `TurboismPlugin` 또는 `CubismPlugin`과 같은 하위 인터페이스를 구현합니다.

```java
public interface TurboismPlugin {
    default void init(PluginContext context) throws Exception {}
    default void enable() throws Exception {}
    default void disable() throws Exception {}
    default void shutdown() throws Exception {}
}
```

- `init`: 컨텍스트를 보관하고, 구성 스키마를 등록하고, 플러그인 전용 상태를 만듭니다.
- `enable`: 액션, 이벤트, UI, 작업 및 기타 활성 동작을 기여합니다.
- `disable`: 런타임이 플러그인 스코프를 닫기 전에 활성 동작을 중지합니다.
- `shutdown`: 스코프가 소유하지 않는 플러그인 전용 리소스를 해제합니다.

하나의 JAR에 순서가 지정된 여러 진입점이 포함될 수 있습니다. 생성, 초기화 및 사용은 매니페스트 순서를 따릅니다. 사용 안 함과 종료는 역순으로 실행됩니다. 시작은 JAR 전체에 대해 원자적입니다.

## `PluginContext`

| 항목 | 용도 |
| --- | --- |
| `descriptor()` | 현재 JAR 수준 `PluginDescriptor` |
| `logger()` | 플러그인 범위 로깅 |
| `paths()` | 구성, 데이터, 캐시, 상태 및 로그 네임스페이스 |
| `localization()` | 로캘, 텍스트 조회 및 서식 |
| `tasks()` | 범위가 제한된 단일 실행 및 고정 지연 작업 |
| `hostReads()` | 범위가 제한된 비동기 호스트 읽기 |
| `storage()` | 플러그인이 소유한 DATA, STATE 및 CACHE 저장소 |
| `userFiles()` | 사용자가 허용한 파일 핸들 |
| `cubism()` | 스냅샷, 통합 오브젝트 접근 및 트랜잭션 호환 진입점 |
| `parameterQuery()` | 범위가 좁은 파라미터 쿼리 |
| `selectionQuery()` | 선택 읽기 및 변경 구독 |
| `modelHierarchyQuery()` | 모델 트리 쿼리 |
| `cubismRead()` | 집계된 읽기 기능 계열 |
| `eventBus()` | 타입이 지정된 이벤트 게시 및 구독 |
| `actions()` 및 `menus()` | 액션 등록 및 메뉴 기여 |
| `mainToolbar()`, `paletteToolbar()`, `contextMenu()` | 타입이 지정된 UI 기여 레지스트리 |
| `uiHost()` 및 `uiScheduler()` | 툴킷 중립적 UI 기능과 UI 스레드 스케줄링 |
| `config()` | 타입이 지정된 플러그인 구성 |
| `diagnostics()` | 현재 구조화된 진단 |
| `disposableScope()` | 역순 수명 주기 정리 |

일부 기본 서비스는 `UnsupportedOperationException`을 발생시키고, 다른 서비스는 명시적인 사용 불가 구현을 반환합니다. 플러그인은 사용할 수 없는 기능 계열을 우회하지 말고 처리해야 합니다.

## 등록과 정리

대부분의 레지스트리는 `AutoCloseable` 핸들인 `Registration`을 반환합니다.

```java
Registration registration = context.actions().register("example.refresh", action);
context.disposableScope().register(registration);
```

스코프는 등록을 역순으로 닫습니다. 액션, 메뉴, UI 기여, 구독, 작업 핸들 및 기타 닫을 수 있는 리소스를 스코프에 넣어 런타임이 플러그인 ClassLoader를 안전하게 해제할 수 있게 하세요.

Cubism 수명 주기 훅은 콜백 등록 버스가 아니라 진입점 인터페이스에서 검색됩니다.

## 액션, 메뉴 및 이벤트

`ActionRegistry.Action`은 ID, 레이블 및 핸들러를 제공합니다. `ActionContext`는 타입이 지정된 UI 액션 이벤트 또는 세대에 바인딩된 컨텍스트 메뉴 선택을 담을 수 있습니다.

`MenuRegistry.MenuContribution`은 슬래시로 구분된 메뉴 경로를 등록된 액션 ID와 순서에 바인딩합니다.

일반 이벤트 버스는 타입이 지정되어 있습니다:

```java
Registration subscription = context.eventBus().subscribe(
    MyEvent.class,
    event -> context.logger().info(event.value())
);
context.disposableScope().register(subscription);
context.eventBus().publish(new MyEvent("changed"));

record MyEvent(String value) implements EventBus.TurboismEvent {}
```

이벤트는 변경 불가능한 플러그인 또는 SDK 소유 값이어야 합니다. 이벤트에 원시 호스트 오브젝트, Swing 위젯, 네이티브 핸들 또는 호스트 ClassLoader를 넣지 마세요.

## 스냅샷 및 쿼리 API

`CubismFacade`는 여전히 변경 불가능한 런타임 스냅샷을 제공합니다:

```java
CubismRuntimeSnapshot runtime = context.cubism().runtime();
Optional<ProjectSnapshot> project = context.cubism().activeProject();
Optional<DocumentSnapshot> document = context.cubism().activeDocument();
Optional<ModelSnapshot> model = context.cubism().activeModel();
boolean hostPresent = context.cubism().isHostPresent();
```

범위가 좁은 쿼리 서비스는 다음과 같습니다:

- 파라미터 조회와 열거를 위한 `ParameterQueryService`;
- 현재 선택과 선택 변경 구독을 위한 `SelectionQueryService`;
- 모델 트리 순회를 위한 `ModelHierarchyQueryService`;
- 프로젝트, 문서, 모델, 선택, 파라미터, 모델 오브젝트, 메시, 디포머, PSD, 클립 마스크, 텍스처 아틀라스, 렌더 상태, 워크스페이스 및 테마 상태 읽기 계열을 위한 `CubismReadCapabilityService`.

스냅샷과 쿼리 값은 호스트 오브젝트 참조가 아니라 변경 불가능한 DTO입니다.

## 통합 Cubism 오브젝트 그래프

새로운 플러그인 코드는 통합 오브젝트 API를 우선 사용해야 합니다:

```java
CubismModel model = context.cubism().model().active();
Parameter parameter = model.parameters().find(new ParameterId("ParamAngleX"));

float value = parameter.getValue();
parameter.setValue(value + 1.0f);
```

`CubismModel`은 Parameters, Parameter Groups, Parts, Drawables, Deformers, Warp 및 Rotation Deformer, Glue, Canvas, 모델 업데이트, 기본 키폼 잠금 및 파라미터 바인딩 작업을 노출합니다.

강한 ID에는 `ProjectId`, `DocumentId`, `ModelId`, `ModelObjectId`, `ParameterId`, `ParameterGroupId`, `PartId`, `ArtMeshId`, `DeformerId`, `GlueId` 및 `ParameterBindingPointId`가 있습니다.

모델과 그 자식은 세대에 바인딩됩니다. 참조는 문서 전환, 다시 로드, 삭제, 플러그인 사용 안 함, 프로바이더 교체 또는 기타 무효화 수명 주기 이벤트 후에 안전하게 실패합니다.

## 작업 수명 주기 훅

`CubismPlugin`은 Parameter, Part, Drawable, Deformer 및 Model 훅 계열을 결합합니다.

```java
public final class ClampPlugin implements CubismPlugin {
    @Override
    public float beforeSetParameterValue(Parameter parameter, float value) {
        return Math.min(value, parameter.getMaximumValue());
    }

    @Override
    public void onParameterValueChanged(
        Parameter parameter,
        float oldValue,
        float newValue
    ) {
        // Runs only after authoritative state changed.
    }

    @Override
    public void afterSetParameterValue(Parameter parameter, float value) {
        // Observe normal completion; do not perform a second mutation.
    }
}
```

```text
before -> canonical operation -> authoritative state probe -> on(changed only) -> after(normal completion)
```

- `before`는 동기적이고 순서가 있으며 인수를 재작성할 수 있습니다.
- `on`은 관찰 가능한 변경에만 발생합니다.
- `after`는 정상 완료를 관찰합니다.
- 관찰 권한과 가로채기 권한은 별개입니다.
- 플러그인은 바이트코드 트랜스포머를 직접 등록할 수 없습니다.

## 구성

타입이 지정된 구성은 스키마, 코덱, 순차 마이그레이션, 비동기 읽기 및 리비전 기반 compare-and-set 쓰기를 지원합니다.

```java
ConfigKey<Boolean> enabled = new ConfigKey<>(
    "example.settings",
    "enabled",
    true,
    ConfigCodecs.booleanValue()
);

ConfigSchema schema = new ConfigSchema(
    "example.settings",
    "settings.json",
    1,
    List.of(enabled)
);

context.config().registerSchema(schema, List.of());
context.config().read(enabled);
context.config().write(enabled, true, expectedRevision);
```

런타임은 플러그인 설정을 `config/<pluginId>/` 아래에 저장합니다. 플러그인은 `turboism.home` 아래의 경로를 직접 구성해서는 안 됩니다.

## 플러그인 저장소와 사용자 파일

`PluginStorage`는 세 루트 아래에서 원자적 읽기, 쓰기, 복사, 이동, 목록 및 삭제 작업을 제공합니다:

- 영구 비즈니스 데이터를 위한 DATA;
- 다시 만들 수 있는 런타임 상태를 위한 STATE;
- 다시 만들 수 있는 캐시 데이터를 위한 CACHE.

```java
StoragePath path = new StoragePath(StorageRoot.STATE, "manual-order.txt");
context.storage().writeUtf8Atomic(path, "a\nb\n");
context.storage().readUtf8(path, 256 * 1024);
```

경로는 정규화된 상대 경로여야 합니다. 사용자가 선택한 외부 파일은 `UserFileAccessService`와 스코프가 지정된 `UserFileHandle` 오브젝트를 사용하며, 사용자 파일은 제한 없는 파일 시스템 기능이 아닙니다.

## 작업과 비동기 읽기

관리되지 않는 스레드, 실행기 또는 타이머를 소유하는 대신 `PluginTaskScheduler`를 사용하세요.

```java
TaskSubmission submission = context.tasks().submit(
    new PluginTaskRequest(
        new TaskId("refresh"),
        PluginTaskKind.COMPUTE,
        PluginTaskPriority.NORMAL,
        token -> token.checkCanceled()
    )
);
```

작업은 타입이 지정된 제출, 취소, 완료, 시간 초과, 거부, 백프레셔 및 회로 열림 결과를 노출합니다.

`AsyncHostReadService`는 의도적으로 작은 의도 집합을 가집니다. 현재 SDK에 존재하는 의도만 사용하고 향후 파라미터, 메시 또는 PSD 의도를 가정하지 마세요.

## UI API

UI API는 Swing/AWT나 호스트 위젯이 아니라 SDK DTO를 사용합니다. 현재 계열은 다음과 같습니다:

- 액션과 메뉴;
- 메인 및 팔레트 도구 모음;
- 타입이 지정된 컨텍스트 메뉴와 컨텍스트 선택;
- 오버레이, 대화 상자, 상태 알림, 캔버스 힌트 및 파일 선택;
- 툴킷 중립적인 `PanelView` 임베디드 패널;
- UI 스레드 스케줄링;
- canvas-hint 알림(`turboism.ui.canvas.hint` 권한);
- 장면 테이블, 모양, 컨트롤 모양 및 선택된 Editor 기여.

각 UI 계열은 독립적인 기능과 프로바이더 근거를 가집니다. 하나의 계열을 사용할 수 있다고 해서 다른 모든 계열이 활성화되지는 않습니다.

## 권한, 기능 및 작업

- **권한**은 위험 경계를 넘는 것을 허가합니다.
- **기능**은 현재 프로바이더와 호스트 버전이 어떤 기능 계열을 지원하는지를 나타냅니다.
- **작업**은 하나의 구체적인 호출 및 진단 정체성입니다.

권한은 작업 검증을 우회하지 않으며 없는 프로바이더를 만들지 않습니다.

## 플러그인 간 이벤트 계약

스키마 4를 사용하는 플러그인 디스크립터는 자신이 내보내고 가져오는 공개 이벤트 타입을 선언할 수 있으며, 각각은 계약 버전과 이벤트 타입의 ABI 다이제스트에 바인딩됩니다. 런타임은 ClassLoader 위임 없이 그 계약을 해석하고, 중복 내보내기를 거부하며, 프로바이더 계약이 허용되지 않은 가져오기를 거부합니다. 이벤트 계약 선언은 호스트 쓰기 권한을 부여하지 않으며, 플러그인 소유 이벤트 타입을 다른 플러그인이 소비할 수 있게 할 뿐입니다. [플러그인 매니페스트 및 패키징](../build-a-plugin/manifest)을 참고하세요.

## 비계약 공개 타입

일부 클래스는 공유 내부 도우미가 필요로 하기 때문에 public SDK 클래스로 컴파일되지만, 해당 클래스 자체의 문서는 이것이 안정적인 플러그인 API 표면에 속하지 않는다고 명시합니다. 현재 예는 `dev.turboism.sdk.cubism.ActiveReadProjections`입니다.

이 타입을 호출하지 말고, 그 시그니처를 호환성 약속으로 취급하지 마십시오. 생성된 레퍼런스에 실려 있는 이유는 이것이 이미 릴리스된 바이트코드에 존재하기 때문이며, 그 사유는 [생성된 API 레퍼런스](./generated-api)에 기록되어 있습니다.

## 버전 및 준비 상태 참고

- 파라미터 작성 쓰기는 검증된 Cubism 5.3.02 경로를 가지지만, 호출자는 여전히 사용 불가 상황과 오래된 대상을 처리해야 합니다.
- Part 표시 이름 쓰기는 5.2.03과 5.3.02에서 실제 호스트 근거를 가집니다.
- Part 불투명도 작성 쓰기는 5.2.03에서 주장해서는 안 됩니다.
- Cubism 5.3.03은 자체 텍스처 아틀라스 작성 프로바이더, 선택자 계약 및 레이아웃 프로바이더를 갖춘 허용된 정확한 버전이며, 물리, 성능 지표, 프로젝트 수명 주기, 모델 통계 및 시작 억제를 위한 정확한 버전 프로필도 가집니다. 허용은 기능별이며 모든 작업 계열에 대한 일괄 보장이 아닙니다.
- 히스토리 DTO(`HistoryEntry`, `HistoryChange`, `HistoryEditContext`, `HistoryGroup`, `HistoryOrigin`, `HistoryTarget`)는 범위가 제한된 변경 불가능한 의미 투영입니다. 호스트 쓰기 권한을 부여하지 않습니다.
- 가짜 및 정적 테스트는 그 이름이 붙은 계층만 증명합니다.
- 스냅샷/쿼리/트랜잭션 호환 표면은 현재 통합 오브젝트 그래프와 함께 존재합니다.
