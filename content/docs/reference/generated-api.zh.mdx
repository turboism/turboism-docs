SDK Javadoc 必须从对应的 Turboism 源码生成，并在完成审查后才能同步到 SDK 文档站点。

## 文档更新流程

当公共 SDK、SDK 说明或版本发生变化时：

1. 使用源码仓库的 `:sdk:javadoc` Gradle 任务生成 Javadoc；
2. 核对精确版本，并拒绝带有 snapshot 标识的输出；
3. 审查每个可公开搜索的包和类型；
4. 确认内部实现类型和未经批准的 Preview API 没有被当作公共契约；
5. 检查生成文字中是否包含私有资料、本地路径、凭据、宿主日志或仅供内部实现使用的验证信息；
6. 将通过审查的结果同步到文档站点；
7. 运行文档 lint、类型检查和生产构建。

生成成功不代表可以发布。如果生成的公共面或版本尚未准备好，应保持现有托管 Javadoc 不变，并在本页记录阻塞原因。

## 当前状态

最近审查的候选结果没有同步，原因包括：

- 某个生成类型自述为内部且非稳定，但仍可公开搜索；
- 某个生成服务仍标记为 Preview，其公共参考策略尚未批准；
- 已审查的候选结果使用了错误的版本标识。

在这些问题解决前，请使用 [SDK API 指南](./sdk-api)和公共 SDK 源码声明。不要依赖当前托管的 HTML 参考作出发布、部署或兼容性声明。
