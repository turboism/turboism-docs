Turboism은 Live2D Cubism Editor를 위한 Java 17 런타임 향상 도구이자 플러그인 프레임워크입니다. 개발은 폐기된 M1–M16 마이그레이션 순서가 아니라 사용 가능한 프레임워크 및 제품 기능을 기준으로 구성됩니다.

이 페이지는 현재 개발 브랜치를 소스에 근거해 정리한 스냅샷입니다. 릴리스 공지가 아니며, 공개된 버전은 [릴리스 피드](./use/update-policy)를 사용하세요.

## 현재 아키텍처

```text
Plugin -> SDK -> Runtime policy -> versioned Adapter/Provider -> Cubism/Editor
```

플러그인은 Turboism SDK에만 의존합니다. 호스트 접근, 수명 주기, 안전, 스레딩, 트랜잭션, 진단, 호환성 및 버전 라우팅은 런타임이 담당합니다.

## 지원하는 호스트 버전

- 지원되는 Cubism 호스트 플랫폼은 Windows x64입니다.
- Cubism Editor **5.2.03**, **5.3.02**, **5.3.03**은 버전 라우팅 어댑터와 프로바이더를 갖춘 정확한 허용 버전입니다.
- 목록에 없는 Editor 버전은 호환성을 주장하지 않으며, 지원되지 않거나 검증되지 않은 기능은 안전하게 실패합니다.
- macOS 패키징은 미리 보기 전용이며 검증된 호스트 지원이 없습니다. Linux는 설치 프로그램과 페이로드 동작만을 대상으로 합니다.

## 릴리스와 배포

- `stable`, `beta`, `nightly` 세 채널을 가진 하나의 제품 정체성. 각 채널은 동일한 네 가지 패키지 형식을 생성합니다.
- 제품 릴리스는 읽기 전용 후보 빌드와 명시적으로 보호되는 GitHub 승격 단계로 나뉩니다. 후보 빌드가 실패하면 의도한 버전을 재사용하며, 승격만이 주석 태그를 만들고 재빌드 없이 검증된 바이트를 공개합니다.
- 모든 빌드는 버전, 채널, 빌드 번호, 소스 리비전 및 변경 플래그를 담은 전역 빌드 정체성을 포함합니다(`FrameworkBuildInfo`).
- `api.turboism.dev`의 릴리스 API는 에셋별 SHA-256과 체크섬 파일로 모든 채널을 미러링하고, 공식 미러와 GitHub 소스를 해석하며, 릴리스별 다운로드 요청을 보고합니다.
- 검토된 릴리스 노트는 영어를 대체 언어로 두고 중국어 간체와 일본어 번역을 함께 제공합니다. 다이제스트가 정확한 영어 섹션과 더 이상 일치하지 않는 번역은 재사용하지 않고 거부합니다.
- 설치 프로그램은 영어, 중국어 간체, 일본어 및 한국어로 제공됩니다. 설치 프로그램 언어는 설치 프로그램 범위에만 적용되며, 런타임 언어는 런타임 `locale` 설정에서 결정되고 플러그인 인터페이스 언어는 Cubism Environment Settings 언어를 따릅니다.

## 프레임워크 기반

- Java Agent 부트스트랩, 런타임, SDK, 기본 제공 플러그인, 테스트 프레임워크 및 통합 테스트 모듈.
- 플러그인 메타데이터 스키마 버전 **2**, **3**(필수 `category`와 범위가 제한된 `tags` 추가), **4**(선언된 이벤트 가져오기와 내보내기 추가)와 버전별 엄격한 검증.
- 로컬 플러그인 JAR 검색, 매니페스트와 API 범위 검증, 종속성 해석, 플러그인별 하나의 ClassLoader, 수명 주기 실행, 역순 종료 및 스코프/ClassLoader 정리.
- JAR별로 순서가 지정된 다중 진입점과 JAR 전체 시작 롤백.
- 로깅, 경로, 현지화, 작업, 구성, 저장소, 사용자 파일, 이벤트, 액션, UI 기여 및 Cubism 접근을 위한 `PluginContext` 서비스와 진단.
- 관리형 로컬 JAR 설치, 교체, 사용, 사용 안 함 및 제거. 변경 사항은 저널에 스테이징되어 Cubism 재시작 후 적용되며, 코어 플러그인은 비활성화하거나 제거할 수 없습니다.
- 시작 사전 검사는 적용 전에 스테이징된 페이로드 신원(SHA-256, 크기, 디스크립터 해시)을 다시 검증하고, 비공개 백업/복원이 실패한 교체 적용을 보호합니다.
- 프레임워크 메시지 카탈로그는 기본 제공 플러그인과 동일한 로캘 매트릭스를 적용받으므로, 카탈로그가 없으면 조용히 영어로 저하되지 않고 빌드 게이트가 실패합니다.

## 설치 프로그램과 배포

세 가지 패키징 경로가 하나의 스테이징된 페이로드와 Full/Thin/Lite 플러그인 모델을 공유합니다:

- Full과 Lite에 더해 선택적 관리형 GraalVM 구성 요소를 제공하는 Windows 네이티브 NSIS 설치 프로그램(`TurboismInstaller-<version>.exe`);
- Full, Thin, Lite를 제공하고 Windows, macOS, Linux에 설치되는 Java 17 IzPack 설치 프로그램(`TurboismInstaller-<version>.jar`);
- 이식 가능한 `turboism-<version>-full.zip` 및 `turboism-<version>-lite.zip` 아카이브.

두 설치 프로그램 모두 네 가지 필수 확인 항목과 전체 현지화된 런타임 선언을 통과해야 설치를 진행합니다. 어느 것도 Cubism 설치 파일을 수정하지 않습니다. `config.json`의 업데이트 소유권은 명시적입니다. 기존의 유효한 문서에서는 설치 프로그램이 관리형 플러그인 선택만 변경하고, 인식된 레거시 스키마는 페이로드를 변경하기 전에 마이그레이션하고 검증합니다. Windows 설정 도구는 정확히 지원되는 Cubism 설치만 나열하며, Turboism이 소유한 바로 가기를 선택적이고 해시로 보호되는 공식 BAT 통합과 분리해 유지합니다.

## Cubism 및 Editor API 진행 상황

- 통합 오브젝트 그래프가 Canvas, Parameters, Parameter Groups, Parts, Drawables, Deformers, Warp 및 Rotation Deformer, Glue, 파라미터 바인딩 및 텍스처 아틀라스를 포괄합니다.
- Core 기반 읽기는 변경 불가능한 복사 데이터, 버전 정규화, 세대에 바인딩된 오래된 참조 거부 및 다이제스트로 고정된 리졸버 근거를 사용합니다.
- 파라미터 작성 경로는 `Parameter.setValue`를 Editor 작업, 권한 확인, Undo, 변경 상태 처리, 새로 고침 및 오래된 대상 거부에 연결합니다.
- Part 표시 이름 쓰기는 5.2.03과 5.3.02에서 실제 호스트 근거를 가집니다. Part 불투명도 작성 쓰기는 5.3.02에서 근거를 가지며, 관찰된 평가 setter가 네이티브 Part Undo에 참여하지 않았기 때문에 5.2.03에서는 의도적으로 사용할 수 없습니다.
- Cubism 5.3.03은 자체 허용된 텍스처 아틀라스 작성 프로바이더, 선택자 계약 및 레이아웃 프로바이더와 함께 물리, 성능 지표, 프로젝트 수명 주기, 모델 통계 및 시작 억제를 위한 정확한 버전 프로필을 가집니다.
- 파라미터 수명 주기 훅은 순서가 있는 동기 `before` 재작성, 변경 시에만 발생하는 `on`, 정상 완료 시의 `after`, 재귀 거부, 범위가 제한된 관찰 작업 및 언로드 정리를 지원합니다.
- 히스토리는 이제 변경 불가능한 의미 정보를 투영합니다: `HistoryEntry`, `HistoryChange`, `HistoryEditContext`, `HistoryGroup`, `HistoryOrigin`, `HistoryTarget`과 대상, 좌표 및 그룹화에 대한 범위가 제한된 검증. 이러한 값은 호스트 쓰기 권한을 부여하지 않습니다.
- 현재 페이지 텍스처 아틀라스 레이아웃 계약은 검토된 SDK 호환성 기준선(v8)으로 바인딩되며, 유지되는 생성자에 대한 연결 게이트를 가집니다.

## 기본 제공 플러그인

검토된 번들에는 열일곱 개의 플러그인이 포함됩니다: 텍스처 아틀라스 패킹, 메시 미러 축 편집, 파라미터 일괄 전송, 물리 편집, 팔레트 탭 필터, PSD 클립 마스크 가져오기, 히스토리 패널, 최근 미리 보기 썸네일, WebDAV 자동 백업 동기화, 클립 마스크 뷰어, 텍스처 아틀라스 통계, 성능 통계, UI 테마, 팔레트 레이블 스타일, 장면 팔레트 향상, 루프백 MCP 서버 및 내장 코어 플러그인. [기본 제공 플러그인](./use/first-party-plugins)을 참고하세요.

## 공유 플러그인 서비스와 UI

SDK에는 다음에 대한 계약이 포함됩니다:

- 액션과 메뉴;
- 메인 및 팔레트 도구 모음;
- 타입이 지정된 컨텍스트 메뉴;
- 툴킷 중립적인 임베디드 패널;
- 오버레이, 상태 알림, 대화 상자 및 파일 선택;
- 타입이 지정된 플러그인 구성과 마이그레이션;
- 플러그인이 소유한 데이터, 상태 및 캐시 저장소;
- 범위가 제한된 작업과 취소;
- 비동기 호스트 읽기;
- 현지화와 진단;
- 모양, 장면 테이블 및 선택된 Editor 기능군.

호스트 및 UI 기능군은 일치하는 프로바이더나 검증된 호스트 기능을 사용할 수 없을 때 안전하게 실패합니다. 가짜 또는 정적 테스트는 실제 호스트 준비 상태를 자동으로 확립하지 않습니다.

## 검증 모델

검증은 하나의 구분 없는 게이트로 실행되지 않고 비용과 위험에 따라 계층화됩니다:

```text
focused verification      smallest affected compile or test selection
devCheck                  production compilation plus structural boundaries
checkIntegration          packaged runtime, plugin, bundle, and cross-module behavior
checkCompletedCommit      full automated repository gate for a coherent change
checkRelease              completed-commit plus supply-chain, historical, and installer-artifact checks
host validation           explicit exact-version Cubism execution for the affected feature
```

호스트 검증은 감독되는 로컬 큐를 통해 실행됩니다. 빌드와 준비 작업은 병렬로 실행될 수 있지만, 단일 호스트 승인 잠금이 실제 Cubism 세션을 직렬화하고, 완료에는 일치하는 구조화된 수명 주기 및 정리 근거가 필요하며, 소유권이 불분명하면 관련 없는 세션을 종료하는 대신 검사를 위해 호스트를 격리합니다.

## 공식 디렉터리 상태

내장된 서명된 공식 디렉터리 클라이언트와 UI가 구현되어 있지만 프로덕션 활성화는 준비되지 않았습니다. 프로덕션 키 목록이 비어 있고 실제 서명된 카탈로그 준비 상태가 확립되지 않았습니다. 이는 라이브 마켓플레이스가 아닙니다.

## 진행 중이거나 버전 제한이 있는 항목

- 많은 통합 오브젝트 쓰기 메서드가 여전히 특정 버전 프로바이더에 의존합니다. 인터페이스에 메서드가 있다고 해서 지원되는 모든 Cubism 버전에서 실행할 수 있는 것은 아닙니다.
- 전체 Editor 작성 매트릭스는 여러 작업군에 대해 여전히 불완전하며, 작업군별 준비 상태는 [SDK API 가이드](./reference/sdk-api)에 기록됩니다.
- Drawable, Deformer, Glue, 메시, PSD 및 추가 텍스처 아틀라스 워크플로는 소비자 주도의 구현과 정확한 검증이 필요합니다.
- 호스트 UI 부착, 고빈도 훅 및 실제 호스트 준비 상태는 정확한 버전 게이트가 있는 고위험 경계로 남아 있습니다.
- 업데이트 확인은 현재 안정 릴리스의 일부가 아니며, 업데이트는 설치 프로그램을 수동으로 다시 실행하는 것입니다.
- SDK HTML Javadoc을 생성할 수 있고 이 사이트에 호스팅되지만, 많은 공개 선언에 여전히 더 나은 설명 주석이 필요합니다.

## 현재 약속하지 않는 것

Turboism은 현재 다음을 약속하지 않습니다:

- 설치 프로그램 패키지를 위한 서명되거나 공증된 공개 릴리스 채널;
- 검증된 macOS Cubism 호스트 지원;
- 프레임워크 또는 플러그인 업데이트의 자동 다운로드 및 설치;
- 프로덕션 활성화된 마켓플레이스, 게시자 서명 또는 폐기;
- 완전한 사용자 대상 설치, 복구, 롤백, 되돌리기 및 완전 제거 UI;
- Cubism 런처의 전역 수정;
- 모든 Cubism 버전에 걸친 일관된 기능 준비 상태;
- 가짜, 정적 또는 단일 버전 근거만에 기반한 프로덕션 준비 상태.

## 단기 우선순위

1. 통합 오브젝트 및 참조 모델을 완성합니다.
2. Core 읽기와 버전 라우팅 프로바이더를 완성합니다.
3. 검증된 소비자로부터 Undo를 포함한 Editor 소유 쓰기를 확장합니다.
4. 작업 수명 주기 의미를 표준화합니다.
5. 프로젝트, 선택 및 모델 트리 API를 완성합니다.
6. SDK 전용 플러그인을 통해 나머지 기본 제공 워크플로를 복원합니다.
7. 명시적 API, 새로 고침, 폴링 또는 콜백이 충분하지 않을 때만 훅을 추가합니다.
8. 서드파티 SDK, 패키징 및 릴리스 근거를 강화합니다.

소스 수준 맥락은 [Turboism 저장소](https://github.com/Turboism/Turboism)와 그 `ARCHITECTURE.md`, `ROADMAP.md` 파일을 참고하세요.
